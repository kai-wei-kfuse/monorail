最终补记（v1.22）：coder 已接手实现并完成审核、451 项测试、静态/事件回归、正式及隔离原生构建和 24 次真实 IPC 对照；P2d 完成。详见 [最终审核](0.2.5-p2d-review.md)；以下首审意见保留历史语境，不再作为阻止已接受方案实施的门禁。

- `src/app/shell/QuickActs.tsx:40` 在回调后安排 650ms 再 setOpen(false)，最早也需等该期限；`:49` 的 pressed 来自已提交 current。删除该 timer 能直接去掉这部分等待，也消除旧 timer 在重开后又关闭弹层的路径。
- `src/services/commit.ts:97` 已用 Promise.all 同时读取四类实体，不能称为“四个目录全部串行”。`src/data/mdRepo.ts:21-28` 的每个目录内部确实逐文件串行。
- 已核对安装的 Tauri SDK `path.js:731-733,745-747`，join/dirname 确实调用原生 invoke，不是零成本前端函数。
- 存在文件的当前 read 有 join、exists、stat、readTextFile 共 4 次调用。拟移除 join 并行 stat/text 后，仍是 exists、stat、readTextFile **3 次调用、2 个依赖阶段**；不是“4 次 IPC 减到 2 次”。四目录本来并行，不能把总调用数量当成全部串行的往返数量。
- 方案中的“60 个实体、240+ 次、400–800ms”没有相应实际数据规模/时序日志，需标为示例或待验证假设。并行读取能缩短等待链，但解析仍运行于同一 JS 线程，缓存深拷贝本身也有成本。

## 低层方案必须修订的部分

### 1. 路径辅助函数对合法 Windows 根目录不等价

方案 §2.2 的 cleanRoot/parentOf 示例对 `C:\` 或 `C:/` 的 `settings.yaml` 得到父目录 `C:`；原生 dirname 应返回绝对根 `C:\`。扩展盘符根 `\\?\C:\` 也丢掉最后的根分隔符。`C:` 是盘符相对路径，可能解析到该盘当前目录或被 scope 拒绝，不能拿它替代根目录 mkdir 的参数。

已用原方案函数与 Node win32 路径语义做只读对照：[检查脚本](quickacts-path-plan-check.mjs)、[实际失败日志](0.2.5-quickacts-path-plan-check.log)，退出码 1。普通目录、Unicode/空格和普通 UNC 对照通过，盘符根及扩展盘符根不通过。没有向这些示例路径写文件。

**要求：** 定义 Windows 本地辅助函数的输入/输出契约，保留绝对根及 UNC/扩展路径语义，不改变 safeRelative 边界。补普通盘符目录、盘符根、正反斜杠与尾分隔符、UNC share、扩展盘符根、Unicode/空格和非法相对路径测试。只提取当前数据层所需的本地路径处理，不增加通用路径框架或默默退回原生 API。

### 2. 缓存需要首次返回值隔离与生命周期契约

按实例缓存成功解析的实际磁盘 `(version,text)` 快照、每次仍读盘、命中后深拷贝的方向成立。schema 是每个 MdRepo 实例固定传入，且实体可通过 passthrough 含有嵌套未知字段。

方案只说明命中后克隆，但**首次解析时也不能把同一个可变 Entity.value 同时入缓存并原样返回**，否则首次调用方修改嵌套字段就污染缓存。需明确缓存独立副本与每次对外副本的隔离。

另外明确：只缓存 decode/schema 成功的快照；读取/解析错误照常抛出，不返回旧缓存；缺失文件仍返回 null，枚举后消失仍报 Entity disappeared；清理已删除文件的缓存。write/remove 返回的是待提交 Write，不能据此提前把未提交值当作缓存事实。原 mtime/version 与 Journal.before 文本检查保持；缓存只派生于真实磁盘读取，不成为第二个存储来源。

测试覆盖首次返回与后续命中对象修改隔离、嵌套未知字段、相同 version 不同 text、相同 text 不同 version、删除/重建、非法文件修复、失败读取传播、Write 生成但未提交与 journal 失败后的读盘结果。不要用“100% 安全”代替这些不变量和实际证据。

### 3. 并行化与边界保持

Promise.all 保持输入顺序，可替换 MdRepo 内串行读取；保留错误传播，不用 allSettled 丢掉失败实体，也不引入任意并发上限或静默空列表。stat 与 readTextFile 并行仍不是原子文件快照；原实现也不保证原子快照，不应声称因此获得更强的外部编辑保证。保持真实快照内容及现有写入/Journal 校验，并测试读取中消失或任一请求失败时的显式错误。

Timelog 分组的 push 优化可以只修改局部新建 Map/数组，不得改变输入条目、启动索引或把未提交条目写入已提交索引；保留最终顺序和既有变化日写入比较。

## 验证与文档要求

UI A 可先实现并验证磁贴、数字键、睡觉及临时表单均点击即收起、快速重开不受旧 timer 影响、点击时刻 at 仍准确；事务失败继续走原有错误报告，不以乐观 store 绕过提交。

低层缓存/IO 涉及共享数据边界，按项目结构性修复和中型计划变更规则补 ADR，写明上述不变量与方案取舍后再交审核。当前没有相应新 ADR，不直接开始低层实现。

性能验证应记录实际数据规模、文件/IPC 调用计数、冷/热轮次与分阶段耗时：点击→收起、排队、读取/解析、journal 写入、publish→抽屉可见。先留基线，再分项比较，区分消除 650ms 和真实提交提速。可在独立测试副本、开发/验证入口计时；不要控制或重启用户正在手测的窗口，不读取修改日常数据，不把合成延迟基准冒充真实 Tauri IPC 性能。
