## 已修（本次提交）

- 修复：「离开中」读数旁的状态点看不见。原因是 `@container card (max-width: 1100px)` 里 `.t-row i { display: none }` 本来要藏英文状态词，但状态点也是 `<i>`，一起被藏了。窗口 1000 宽时，所有状态的点都没有。点改成 `<span class="dot">`，和参考实现一致。实测颜色：待开始 #bcbcb6；进行中 #161616 加强调色外圈；离开中 #00b4ff（02/04/14）。
- 核对：标题栏状态块的灯。待机 #fffa00，专注 #00ffa2，离开 #00b4ff，均为 7×7，符合 §6。
- 修复：卡片宽度小于 1100 时，首页按钮没有收窄，英文小字也没有藏（§7.2）。在 home.css 加了 container query，只作用于首页卡片的按钮（02/04）。
- 修复：快捷活动弹层的标题顺序改成中文在前、英文在后（参考 05：「快捷活动 QUICK ACTIONS」）。
- 修复：快捷活动磁贴补上英文小字。能认出的图标（厕所、快递、吃饭、拉伸）配英文；认不出的不写，免得写错（03）。

## 符合规范（已核对，不用改）

- 首页卡片占内容区全部（≥80%）；全部直角；按钮有 3px 厚度阴影；主按钮的图标块是强调色，次按钮的是黑色（01/14）。
- 竖排标签条、L 形角标加黑色小方块、◎ 标记、进度竖条（两端引导条、刻度格、▲ 指针）、等高线背景，都和参考 02 一致（14）。
- 宽窗口下「ELAPSED 已用」和英文状态词都显示；窄窗口下按 §7.2 隐藏（02 对 14）。
- 小窗 520×88：左边 24px 黑条（格号 + ▼▼）、等高线浅色区、30 格竖条、黑色计时块（左上切角、右下切角）、强调色主按钮、灰色「还原」按钮，和参考 06 一致；没有整块黄色（05）。
- 对话框：黑色顶条加一段强调色、英文小字 + 中文标题、浅色控件、主按钮黑底（06/07）。
- 通知：左侧 5px 强调色竖条，右边贴 1px 黑线，从右下滑入（08/12）。
- 引导卡、停止出卡卡沿用同一张卡的样式：竖排标签条 GUIDE/STOPPED，加英文小字和大标题（09/11）。
- 首次使用页有自绘标题栏，可以拖动和关闭（15）。

## 和规范不一致、本次没改（不在我的范围，或需要决定）

- 记录条的期限输入用的是浏览器原生 `datetime-local`，显示「yyyy/mm/日 --:--」，中英混排，看起来像网页控件。不符合 §0.1 第 1 条「桌面软件感」和 §6 的控件风格。文件在 `pages/quickbar/`，不在本次范围（10）。
- 通知位置和参考一样在右下角（§6 和参考 `.toast` 的 bottom:60px），但会盖住首页右下角的大号读数（12）。建议挪到右上、标题栏下方。这一条要你定。
- 说明性通知的文案里有开发用语「（M3 接线）」「（M2 接线）」，用户看不懂。文案在 `app/MainApp.tsx`，归 lead（08）。
- 「今天不再出卡」点一下就生效，没有确认，当天也撤不回来（11）。这是交互问题，不属于视觉，列出来供决定。
- 引导卡的主按钮「设定主线」用的是 ✓ 图标；用 → 更像「去做」（09）。图标属于 GuideCard 的选择，影响很小，没改。

## 其他

- 15:11 启动后，m1-smoke 的 state.yaml 里出现了 3 次 refusals，时间点是 15:11:26/33/42。核对结果：
  - 只有 `cardService.redraw` 和 `shrink` 会写 refusals。卡片文件没有新增，所以排除缩小，这三次是「再抽一张」。
  - 快捷键不可能触发「再抽一张」。`app/shell/hotkeys.ts` 只绑定了 M（小窗）、Q（记录条）、1–9（快捷活动 开始/回来），并且输入框聚焦或对话框打开时不响应。所以快捷键没有误触发这个问题。
  - 我截 probe 图时还是「离开中 · 厕所」；下一次 eval 时状态块已经是「待机 00:01」，说明最后一次是在那之前 1 秒左右。这段时间我的驱动脚本只执行了只读的 `Runtime.evaluate`，没有发送点击和键盘事件。lead 和 Codex 都确认没有操作。
  - 还原数据后再启动并停留了几分钟，refusals 一直是空的，所以不是应用自己触发的。
  - 结论：用户确认这 3 次「再抽一张」和 1 次「回来」是自己在真实窗口上点的，不是 bug。
