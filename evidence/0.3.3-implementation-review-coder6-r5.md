## M1：维护检查串窗、无轮次 ACK 与重复覆盖

截图 `shots/14-real-exit-blocked-toast-on-main.png` 不只有预期 dirty 提示，顶部还出现两条“没有等待中的更新草稿检查”错误。本席没有把它们当作正常全绿，也没有仅要求隐藏 Toast。

代码证据：`src-tauri/src/quick_save.rs:351`–`355` 对多个 target 发送同名 update-check-draft，但只带 requestId；`MainApp.tsx:135`、`QuickBarApp.tsx:100`、`IdeaWindowApp.tsx:160` 使用全局 listen，未过滤目标、未回传请求号。`Gate.record_ack:76`–`109` 接受 None 请求号，responses.insert 会覆盖同窗首份响应，完成后 take pending。

这与本版已发现的 Tauri 全局事件串扰相同：一次检查多次响应能产生额外无 pending 错误；旧轮无 token ACK 也可能进入新轮，重复 clean 可覆盖首份 dirty。这是检查身份和状态同步缺陷，属于结构性修正，不能吞错或加一个放行旁路。

主审已裁定：检查与 restore 绑定 targetLabel/requestId；三窗使用真实本窗 label 过滤，每轮只 ACK 一次；Rust 从实际 WebviewWindow 取 caller、request_id 必填，旧/错/缺号不推进，同轮重复不能覆盖首份 dirty；旧 restore 不解除新轮锁，main 实际输入也按轮锁定，旧 quickbar ACK 入口同源收口。

本席新增 [Rust Gate 回归文件](0.3.3-coder6-maintenance-gate-review-r6.rs)，覆盖旧轮/缺 token/空 token/重复 clean 不盖 dirty/错 caller 不推进。文件待 coder-3 在 quick_save.rs 子测试模块接入并按最终 typed 接口调整，**尚未编译或执行，不称通过**；必填参数的原生缺参拒绝另由新定向 invoke 证明。前端串窗/旧 restore 回归待真实接口交接后编写。只重测 dirty 退出→取消→第二轮 clean 退出，额外无 pending 错误不得再出现；新产物哈希需包含受影响检查模块。
