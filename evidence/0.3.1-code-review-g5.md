## 阻塞

### B1 首页〔缩小〕按钮仍按 `shrinkMaxLevel` / `no_shrink` 置灰，拆两三次以后就点不了了
- `homeProjection.ts:33` 还是 `shrink: no_shrink ? 'locked' : shrink_level >= settings.shrinkMaxLevel ? 'max' : 'ok'`。`CardActions.tsx:16` 在 `shrink !== 'ok'` 时禁用按钮，`HomePage.tsx:144`（从小窗打开缩小）也要求 `shrink === 'ok'`。
- `splitCard` 每拆一次，`today` 卡（原卡）的 `shrink_level` 就加 1（`shrink.ts:37`）。默认的 `shrinkMaxLevel` 是 2，所以同一张卡拆两次以后，首页按钮就灰了，提示「已经缩到最小一级」。服务层 `split` 已经不读上限，所以这只是界面上被挡住，可用户确实没法再拆。这和已定 54「可以一直往下拆」冲突，也和 ADR 第 4 条「`shrinkMaxLevel`、`no_shrink` 不再读」冲突。
- 改法：`homeProjection` 去掉这一段（或者恒为 `'ok'`），`CardActions` 的 `shrink` 属性和 `shrinkTip` 跟着简化，`HomeLook.shrinkMaxLevel`（`HomePage.tsx:69`、`MainApp.tsx:246`、`LivePreview.tsx:65`）一起删。`CardEditor` 里的「不可缩小」开关（`CardEditor.tsx:65`）也是没人读的设置，建议 G6 删设置项时一并去掉，文件照写。补一条测试：同一张卡连拆 3 次，投影里每次都能缩小。

## 应改

### S1 `split` 在插入中、卡暂停时的行为没测，`requireCurrent` 也不看插入状态
- `split` 只调了 `requireCurrent`（`current_card === cardId` 且没有 `rest`）。插入中，原来那张卡还是 `current_card`，所以 `split` 能执行。首页被插入卡盖住，界面上点不到，但小窗的缩小入口（`shrinkFor`，`HomePage.tsx:144`）会弹出对话框。
- 插入中拆分在数据上没问题：原卡 id 不变，回到目标不动。可是 `editContentInTx` 只改开着的那一条的描述（`renameRefInTx`），插入中开着的是插入那条，`card_id` 为 null，所以不会被误改。这一点要靠测试锁住。
- 改法：二选一。一是在 `split` 里加 `insertStateInTx` 检查，插入中直接拒绝，和「插入中不能完成原来那张」（第 2 轮 N4）一致。二是允许，再补一条「插入中拆分、回到任务后接着计的是今天这份」的测试。建议拒绝，规则更简单。

### S2 `renumberTaskInTx` 会把别的任务的卡挤到同一个 `order`
- `order` 是全局序列：`reorderQueue` 按所有卡统一排名（`backpackService.ts:119-125`），新建卡取 `max(order) + 1`（`create.ts:20`、`backpackService.ts:72,89`）。
- `renumberTaskInTx` 只把本任务的卡从 `floor(min)` 开始连续编号。如果本任务的卡原来是 3、7、9，中间夹着别的任务的 4–6、8，重编以后变成 3、4、5、6，就和别的任务的卡撞号了。撞号的卡之间按 `id` 排序（`backpackProjection.ts:20`），顺序变了；`reorderQueue` 会重新排开，但在那之前，「下一项」和队列显示可能不对。
- 改法：不重编，`rest.order = card.order + 0.5` 就够了（`order` 是 `z.number()`，允许小数）。要么就像 `reorderQueue` 那样，在全局序列里只替换本任务的位置。前一种最简单：`order` 只用来排序，用 0.5 不会坏数据，0.3.0 也照样能读。

### S3 今天的量到了的提醒：开着的卡不在今天的板子上时不排，换日跨夜时 `minutesToday` 不对
- `commit.ts:356-359`：`minutesToday = minutesOnDay(去掉开着那条的条目, …, todayKey, …)`，提醒时间是 `open.started_at + (today_minutes − minutesToday)`。如果开着的那条是昨天开始的（跨夜一直在计），它在今天的那一段并没有算进 `minutesToday`，提醒时间却从 `open.started_at`（昨天）开始算，结果是一个已经过去的时间。原生侧对过期的提醒是立即发还是丢，取决于 `reminders.rs` 怎么处理过期的 `at`（我没核对）。
- 改法：提醒的起点用 `max(open.started_at, 今天活动日起点)`，或者直接算 `at = now + (today_minutes − 今天已计(含开着这条))`，计够了就不排。补一条跨夜用例。
- 另外，提醒的 id 里带着 `today_minutes`，改量以后会重新排，这样是对的；但提醒在同一天、同一个量下只会响一次（`fired` 持久化）。暂停后再继续，`minutesToday` 变了，`at` 也变了，id 却没变，原生侧如果按 id 去重，新的时间就不会生效。请核对 `reminders.rs` 是按 id 还是按 id + at 判断「已经发过」：如果是 id，id 里要带上 `open.id`。

### S4 0.3.0 遗留 `state.rest` 的处理：MCP 和首页在换日之前那一刻的行为
- `settleLegacyRestInTx` 只在 `newDay()` 里调用。启动时 `newDay()` 在 `connectApplicationBridge` 之前（`bootstrap.ts`），所以 MCP 看不到这个状态，这是对的。
- 可是 `refreshInTx` 去掉了 `if (tx.state.rest) home_mode = 'rest'`。如果 `settleLegacyRestInTx` 没处理干净（例如开着的不是「休息」，用户在 0.3.0 的休息里又开始了别的事），`rest` 已经清掉，这条路是通的。我核对下来逻辑没问题。
- 要改的是残留代码：`applicationController.ts:93`、`203-208`、`250`，还有 `homeService.ts:245,321` 的 `IN_DEGRADE_REST` 分支，在 0.3.1 里永远走不到了（启动后的第一个事务就把 `rest` 清空了）。可以保留当作防御，但 `nextStepForCode` 里那句「请先在单轨界面完成休息返回」已经没有界面能做到，建议改成「重启单轨」。另外 `homeService.test.ts:133-138` 用 `tx.state.rest = …` 造出来的遗留状态，测的是「从背包开始卡会清掉 rest」，这条路径在真实启动顺序下不会出现，不过留着也无害。

### S5 CLI 两种插入状态的用例：可以不补，但 `--blocking` 要改说明
- 作者问 CLI 的用例要不要补。CLI 测试用的是假后端，插入语义在 `applicationController.test.ts` 里已经测过（这次也补了「插入的事暂停了」那一组），**我同意不补**。方案 G4 那一条，在交接里改成「CLI 走同一个控制器，语义测试在 `applicationController.test.ts`」就行。
- 但 CLI 的 `--blocking`（`cli/commands.ts:539,558`）还照收照传。服务端已经忽略它了，这没问题；只是 CLI 的帮助说明还停在 0.3.0。MCP 的参数描述已经改成「已停用」，CLI 的帮助文字（`cli/output.ts`）请同步，并在 `docs/application/README.md` 写一句。方案 G5 原文要求「描述写 0.3.1 起不起作用」。

## 建议

- **N1 `splitCard` 的「今天已计向上取到 5」和对话框的下限不一致**：服务端是 `a ≥ ceil(今天已计 / 5) × 5`（`shrink.ts:32`），对话框的下限是 `ceil((今天已计 + 1) / 5) × 5`（`ShrinkDialog`）。今天已计正好 10 分钟时，服务端允许 10，对话框最少给 15。差得不多，但用户可能奇怪「为什么不能选 10」。两边取同一个公式就行，建议提一个纯函数 `minTodayMinutes` 共用。
- **N2 `HomePage` 在渲染时算 `todayGoal`**：对话框的默认量是在组件里用 `entries` 现算的，和服务端 `split` 的回落公式重复了一遍（`HomePage` 和 `cardService.ts` 两处 `Math.max(5, ceil((timebox − 总已计) / 5) × 5)`）。建议放进 `domain/plan` 的 `defaultTodayMinutes`，两边共用，免得以后只改一边。
- **N3 `split_note` 和原卡的连带**：`today` 卡没有 `split_note`。G7 的鼠标提示「从哪一项缩小来的」只给 `rest` 卡显示，`today` 卡那一份只在历史里能查到，这和 ADR 一致。G7 写界面时注意：`today` 卡带 SHRINK 标记，但没有鼠标提示。
- **N4 `CompleteDialog` 按钮文字**：开关打开以后，主按钮变成〔先停在这〕，这是新加的文案，计划和 UI 规范里都没有。按方案 G7「开工时给用户看一眼」，和开关说明一起截图给用户确认。
