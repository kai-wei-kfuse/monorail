## 阻塞

### B1 大读数改「今天的」（`refToday`）：开着的那条跨过了换日时间时，会改掉换日之前的时间
- 代码：`domain/timeline/edit.ts:10-31,41-46`。`refStart` 只把**别的**条目裁到 `since`（今天活动日的起点），算出的新起点是 `at − (目标 − 今天已结束的)`，然后把**开着的那一条**的 `started_at` 整个挪到这个时刻。
- 场景（换日时间 4 点）：卡从昨天 23:00 一直计到 05:00，大读数显示今天 1:00。
  - 用户改成 30 分钟：开着那条的起点从 23:00 挪到 04:30，**昨天 23:00–04:00 的 5 小时被删了**。用户只想改今天的。
  - 用户改成 2 小时：起点挪到 03:00，今天的读数还是只算 04:00 以后的 1 小时，界面显示不变；昨天那部分从 5 小时变成 1 小时。
- 这个场景不少见：做到半夜跨过换日时间、前一晚开着的卡忘了停，都会出现。首页、分开布局的任务卡、小窗的读数改的都是 `refToday`（`fused.ts:30`、`TaskCard` 的 `TimeField`、`MiniApp` 的 target）。
- `todayReadout.test.ts` 只测了开着那条是今天开始的情况，没测跨换日。
- 改法（二选一）：
  1. 开着那条开始于 `since` 之前时，先在 `since` 处把它切成两段（换日前那段结束、换日后那段接着开着），再按今天的量改换日后那段。这要经过 `place`，ADR 第 4 条「运行时条目跨日不切片」只是说不自动切，用户主动改读数时可以切，但要在 ADR 里写一句。
  2. 简单做法：这种情况拒绝，提示「这一段跨过了换日时间，在日历里改」。目标值大于 `今天已结束的 + (at − since)` 时也拒绝，提示今天最多能写多少。
- 补测试：跨换日改小、跨换日改大、目标超过今天上限。

### B2 抽屉里编辑事项的〔PASS〕点了只关对话框，PASS 没做
- `BagDrawer.tsx:146`：`<CardEditor … onPass={() => setDlg(null)} />`。`BagActions` 里没有 `pass`，`BagScreen` 也没接 `cardService.pass`。旧背包页是接了的（`1312214:src/app/BackpackScreen.tsx:29`，`passCard → pass(ctx, cardId, at)`）。
- 后果：编辑器里的〔PASS〕还显示着（`CardEditor.tsx` 的 `fm-danger`），`passBlocked` 的提示也还在，用户点了以后对话框关掉，看起来像成功了，其实卡没被放弃。0.3.1 去掉了旧背包页，界面上 PASS 一张卡的入口只剩这一个，现在等于功能丢了，而且是静默失败。
- 改法：`BagActions` 加 `pass(cardId)`，`BagScreen` 接 `cardService.pass`，`BagDrawer` 调它后关掉对话框。再补一条接线测试（`actions.test.ts` 或 `historyActions.test.ts` 那一类），确认能点出 `card.pass`。

## 应改

### S1 今日任务板上正在计的那一行不走秒
- `BagDrawer.tsx:85`：`const runningMs = (() => { …; return run && data.now ? 0 : 0; })();`，两个分支都返回 0。`TodayBoard` 用 `spent = minutesToday + runningMs/60000` 显示正在计那一行，所以这一行只在提交时更新，抽屉开着的时候进度条和「今天已计 / 今天的量」不动。抽屉顶边 `bp-now` 的读数是走的（用 `tick`），两处对不上。
- 方案 R5 的做法是心跳只更新正在计那一行。改成 `tick − Date.parse(data.now.startedAt)` 就行；要更准的话，从投影里取这一行这一段的开始时刻（同 `todaySegStartedAt`），避免把换日前那部分也算进来。

### S2 带过来的项不能逐项去掉
- 已定 4：「预先勾好，用户确认或去掉」。ADR 第 6 条写的是「默认都勾着，〔确认〕〔全部去掉〕，逐项可去勾」。`TodayBoard.tsx:30-34` 只有〔不带〕〔都带上〕两个按钮，`confirmCarryInTx(keep)` 服务端是支持逐项的。
- 用户可以先点〔都带上〕，再逐行〔移出〕，结果一样，但多了一步，也和规则写的不一致。建议在确认条里给每一行加一个勾选框，或者在带过来的行上直接给〔不带〕。

### S3 任务模式关掉后，计时框的自动完成里还能开始卡
- ADR 第 10 条写的是「做卡的入口全隐藏」。G7 隐藏了〔今日任务板〕、抽屉任务页和板子，MCP `start_task_item` 也会报 `TASK_MODE_OFF`。但计时框和小窗的自动完成里还列着卡（`services/suggestSource.ts:31` 不看 `taskMode`，`TimerBar` 的 `onCard → startCard`），日历和列表的「继续这一条」遇到卡的条目也会开始卡（`continueEntryInTx`）。
- 改法：`suggestSource` 在 `taskMode` 关掉时不返回 `cards`。`homeService.startCard` 要不要也挡，作者定；挡的话，「继续这一条」遇到卡的条目可以退回成自由记录（`startOtherInTx`），`MCP` 和界面的行为也就一致了。

### S4 插入卡的〔回到任务〕失败时，插入卡已经被动画收走了
- `InsertCard.tsx:62-75` `back()`：先播放「往上收走」的动画（`fill: 'forwards'`），然后才调 `onBack()`。`onBack` 失败时（比如状态已经变了、`expected_state` 冲突、journal 出错），`finally` 只把 `leaving` 复位，没有撤掉动画。插入卡会停在透明、移出去的状态，数据却还是插入中，首页看起来就是空的。
- 改法：失败时 `getAnimations().forEach(a => a.cancel())`，把插入卡和底下那张卡复位。或者先提交、成功以后再播放动画（不过这样动画会晚一点）。`end()` 不播放动画，没有这个问题。

### S5 首页〔今日任务板〕旁的说明、计时条提示还在说「抽一张卡」
- `TimerBar.tsx:103` 的提示是「点输入框就开始计时；写下在做什么，或者抽一张卡」。首页已经没有抽卡按钮了（已定 41），按钮叫〔今日任务板〕。这是文案，请顺手同步。其他地方我没逐个 grep，作者截图时可以过一遍。

## 建议

- **N1 `BagScreen` 在渲染里发请求**：`BagScreen.tsx:59` 在渲染时 `setLastDraw`，再用 `queueMicrotask` 去调 `onDrawn` 和 `draw`。React 允许在渲染中设置本组件的状态，但在渲染里排副作用不规范；以后打开 StrictMode，或者 React 丢弃一次渲染时，可能会抽两次或漏抽。现在没开 StrictMode（`main.tsx` 没用），可以先不改；改的话，放进 `useEffect(() => { if (drawAt) … }, [drawAt])`。
- **N2 `dueLabel` 按 ISO 字符串的前 10 位比较日期**（`QuestCard.tsx:10-15`）：注释里已经说明了「以投影的 `dueThatDay` 为准」。可背包卡片和详情用的就是这个函数，期限在 0 点到换日时间之间的卡，会标错是哪一天。建议投影直接给每一项一个 `dueDay`（按活动日算），页面只做比较。
- **N3 翻卡的 Esc 和抽屉的 Esc**：`FlipDeal` 在 document 上监听 Esc，`BagDrawer` 也在监听。抽卡前会先 `onClose()` 收起抽屉，所以现在不会冲突。可要是以后有「不收抽屉就翻卡」的入口，两个都会触发。`FlipDeal` 已经 `preventDefault`，`BagDrawer` 也检查了 `defaultPrevented`，但两个都是冒泡阶段的监听器，执行顺序看注册先后。可以把 `FlipDeal` 改成在捕获阶段监听，同 `PlanPopover`。
- **N4 小窗 `todayGoal` 的回落**：`homeProjection` 里卡不在板子上时，`todayGoal` 取的是 `timebox_minutes`（卡的总目标），而缩小、带过去用的是「剩下的时长」（`defaultTodayMinutes`）。首页显示「今天 120 分钟」，缩小对话框里写的是「今天 60 分钟」（剩下的）。建议统一用剩下的时长，或者卡不在板子上时首页写「目标 N 分钟」，不写「今天 N 分钟」。`TaskCard` 现在就是这么分开写的（`todayGoal ? 今天 : 目标`），只要投影在卡不在板子上时给 `todayGoal: null` 就行。
- **N5 G1–G4 的 N2、N3 留到 G9**，同意。G9 的性能用例里，建议顺手量一次每个事务读两份板子文件的开销。

## 已核对、没问题的

- **插入卡**：插入状态的判断用的是 `insertState`，和服务层一致；被插入的是卡还是自由记录，显示不同的文案；回去区域的位置读设置 06；〔结束原任务〕会先弹确认框；插入的事暂停后，〔继续〕在找不到前一段时灰掉，鼠标提示写了原因；上沿那一条、底栏〔↩ 等你回来〕、小窗〔↩ 回到 …〕调的都是 `resume`（回到任务），〔继续〕调的是 `continueTimer`；底下那张卡的内容 `pointer-events: none`，不会被误点。分开布局插入时，计时条显示插入的事（已定 65），插入状态下不显示〔停止〕。
- **抽屉**：抽屉高度 92%、板子宽 380px；Esc 先退出详情再收起抽屉；在抽屉里点〔开始〕后自动收起；从别的页面点〔背包〕会先切回首页；操作历史 ◎ 定位到卡、任务、记录时会拉开抽屉。顶栏的「背包」去掉了，`routes` 同步了。
- **翻卡**：结果不写首页状态；〔开始〕走 `startCard`，〔换一张〕走 `skipCard` 后再抽一次；动效设成「关闭」时不翻，直接开始；「简化」时只淡入那一张；翻开的卡上不写概率。「今天还没排」「先确认带过来的」「插入中 / 休息中」「都做完了」「背包里还没有能做的事」都有对话框，G1–G4 N4 说的点了没反应已经关掉。
- **缩小对话框**：打开时用 `checkSplit` 现算，下限和服务端一致；条子按已计、今天做、剩下的分三段；两句都填了才能确认。
- **追问和临时活动可以选项目**（已定 60–62）：`askChoices` 由离线追问、空闲追问共用；手写的活动名缺省记「未分类」；选「睡觉」「离线」时不套用选的项目；临时活动「存为快捷活动」时，按选的项目写进列表。〔休息一下〕先选项目，缺省是系统项目「休息」，选别的用户项目会经过 `validateUserProject` 校验。
- **任务模式关掉**：抽屉只剩想法池，首页没有〔今日任务板〕，`get_context.today_plan` 返回 null，回顾的押注在 `enter` 和投影两处都按开关过滤；MCP 新错误码 `TASK_MODE_OFF` 的下一步提示也写了。
- **新建任务**：每一项都可以选〔结果 | 时间盒〕，时间盒默认分钟数取设置 01 的时间盒默认时长，少于 5 分钟时不让保存。
