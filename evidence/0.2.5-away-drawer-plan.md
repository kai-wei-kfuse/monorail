### 2.2 [回应 P1-2] `pending`（待确认）与临时活动并存时的优先级与状态转换

后端支持两条进入「`view.pending !== null` 且 `view.away !== null`」的路径：
- **路径 A（先待确认，再插入临时活动）**：点输入框或点「抽卡」产生 `pending`，在未确认前从底栏启动插入型快捷活动或临时活动（`startPreset` 插入模式与 `insert` 不清除 `pending`）。
- **路径 B（临时活动中点 `＋ / 写别的`）**：在临时活动进行中，点击 `TimerBar` / `FusedCard` 的 `＋` 或 `FusedCard` 的「写别的」，调用 `beginPending` 产生 `pending`。

并存期间的规则如下：

1. **视觉呈现优先级**：
   - **右上角 `AwayDrawer`**：只要 `view.away !== null`（`open_entry.kind === '插入'`），`AwayDrawer` 始终挂载在 `.home-stage` 右上角，实时显示临时活动计时。
   - **底层卡片与 `TimerBar`**：当 `view.pending !== null` 时，底层进入待确认工作流：
     - 若存在待做卡（`card?.status === '待做'`）且未点「写别的」（`!write`）：显示该待做卡，状态为 `['待开始 · 已在计时', 'PENDING']`，卡片读数加上 `now - Date.parse(pending.startedAt)`。
     - 否则（无待做卡，或在做卡/自由记录时点了 `＋ / 写别的`）：底层切换为待确认输入框（`WAIT / PENDING / 待确认 · 已在计时`），`useEntry` 解除 `isFrozen`（因 `deciding === true`），允许输入新活动名称、选项目/标签或点选下拉建议（`Suggest`）。
2. **双读数独立可编辑**：
   - **抽屉读数 `#away-elapsed`**：`target = { mode: 'entry', id: away.id }`，修改临时活动本身的开始时刻。
   - **底层读数 `#f-elapsed` / `#elapsed` / `#free-elapsed`**：当 `view.pending !== null` 时启用，`target = { mode: 'pending', id: pending.id }`，修改 `tx.state.pending_at`（后端 `commitReadoutInTx` 校验 `pending_id`，与 `open_entry` 是否为插入无关）。
3. **并存期间的动作语义**：
   - **确认待确认（输入文字回车/失焦调 `startFree`、点待做卡〔开始〕调 `startCard`、或选切换型收藏）**：复用 `claim(entries, pending_at, at)`，按条目实际开始时刻与当前 pending 起点的关系结算，不能把两条路径都解释成保留临时活动直到确认时刻。路径 A 示例：10:00 待确认、10:05 插入、10:10 确认，插入段保留 10:05–10:10，新活动从 10:10 开始。路径 B 示例：10:00 插入、10:05 待确认、10:10 确认，该插入已在 pending 起点之前开始，按原规则在 10:05 截断，新活动从 10:05 开始。修改 pending 读数后仍按实际起点重算；离线条目的特殊保护规则不变。确认关闭临时活动，清空 `pending` 与 `resume_entry_id`，启动新活动并收起抽屉。收藏若自身为插入模式，则按连续插入处理，不承诺清 pending。
   - **取消待确认（按 `Escape` 或点〔放弃〕调 `cancelPending(pending.id)`）**：仅清空 `pending_id` / `pending_at`（若在融合布局「写别的」下则复位 `write = false`；若有待做卡则收起待做卡），**不停止临时活动 `open_entry`，也不清空 `resume_entry_id`**。取消后底层立即恢复显示冻结的 `resumeEntry`（或待机），`AwayDrawer` 继续保留。
   - **点抽屉〔回来〕（`actions.resume`）**：结束临时活动并恢复 `resume_entry_id`（无则转待机），`AwayDrawer` 收起；已有的 `pending` 会话保留不静默丢失。

### 2.3 [回应 P2-3] 抽屉内改读数部分/完全覆盖 `resumeEntry` 的重算与失效退回契约

在 `AwayDrawer` 内通过 `#away-elapsed` 调大临时活动时长（使临时活动 `started_at` 前移）时，完全复用既有 `commitReadoutInTx` -> `setReadoutInTx` -> `place(..., 'switch')` -> `acceptInTx` -> `alignInTx` -> `projectHome` 链路，不设特殊覆盖保护，也不在前端缓存旧时长：

1. **部分覆盖 `resumeEntry`（新起点落在 `(resumeEntry.started_at, resumeEntry.ended_at)` 之间）**：
   - 首次提交返回 `{ kind: 'confirm', hit, plan }`，在抽屉下方显示 `<HitNote />`（`将覆盖：… 〔确定〕〔取消〕`）。
   - 点〔取消〕：不改动任何数据，收起提示。
   - 点〔确定〕：`place(..., 'switch')` 将 `resumeEntry.ended_at` 截短至新起点，`resumeEntry.id` 仍在 `entries` 中，`state.resume_entry_id` 保持不变。`projectHome` 重新投影后，`home.resumeEntry.endedAt`（及任务卡的 `closedEffectiveMs`）自动更新为截短后的时刻，底层卡片读数立即减小为截短后的真实时长，状态保持 `进行中（暂停）`；后续点〔回来〕仍正常恢复该活动。
2. **完全覆盖 `resumeEntry`（新起点 `<= resumeEntry.started_at`）**：
   - 用户在 `<HitNote />` 点〔确定〕后，`place(..., 'switch')` 删除被完整覆盖的 `resumeEntry`。
   - `acceptInTx`（`src/services/tracking/transaction.ts:16`）自动检测到 `state.resume_entry_id` 已不在 `entries` 中，将 `tx.state.resume_entry_id` 置为 `null`。
   - 若原活动是进行中的任务卡且该卡已无其他活跃引用，同事务末尾的 `alignInTx` 因 `activeRef(tx) === null` 将该卡退回 `'待做'` 并清空 `current_card`（`home_mode = 'blank'`）。
   - `projectHome` 发布后，`home.resumeEntry` 为 `null`；由 align 释放的进行中卡不再显示为当前卡。**有 pending 时仍遵守 §2.2 的待确认优先级，保留其 ID、起点和输入，也不擅自移除另抽出的待做卡**；仅当无 pending 且无待做卡时，底层退回空白待机展示（`现在做什么` / `待机 IDLE` / `00:00`）。此时真实正在运行的条目仍是抽屉中的临时活动，底层“待机”只是无返回目标的展示，不创建第二条计时。
   - 随后用户在 `AwayDrawer` 点击〔回来〕时，`resumeInTx` 因 `state.resume_entry_id === null` 直接转为**待机**（`startSystemInTx(tx, '待机')`）并收起抽屉。
3. **确认期间活动已切换**：
   - 若预览期间 `open_entry` 已变为其他条目，点〔确定〕时 `commitReadoutInTx` 校验 `open.id !== request.target.id` 抛错，由 `TimeField` 显示错误提示且不修改新条目。

## 3. 两种布局 × 四类底层状态的完整场景矩阵

| 底层初始状态 | 触发动作 | 融合布局（`fused`）表现 | 分开布局（`split`）表现 |
|---|---|---|---|
| **1. 自由记录进行中**<br>（如「学 408」已计 25:00） | 插入临时活动「上厕所」 | 底层大卡保留「正在做 · 学 408」与项目/标签，输入框只读、分类/标签禁用，底部读数冻结在 `25:00` 且状态为 `进行中（暂停） PAUSED`，底部保留「暂停」「停止」「＋」「抽一张卡」；右上角弹出 `AwayDrawer` 显示「上厕所」实时计时与〔回来〕 | 顶部 `TimerBar` 与下方 `FreeCard` 均保留「学 408」且冻结在 `25:00`，输入框/标题只读、选择器与读数禁用，`FreeCard` 状态为 `进行中（暂停） PAUSED`；顶部保留显式「＋」入口，`.home-stage` 右上角弹出 `AwayDrawer` |
| **2. 任务卡进行中**<br>（如「改简历」已计 35:00） | 插入临时活动「上厕所」 | 底层大卡保留任务卡「改简历」，读数冻结在 `35:00`（禁用点改），状态为 `进行中（暂停） PAUSED`，卡头无旧「回来」链接，卡标题与卡项目/标签仍可改；右上角弹出 `AwayDrawer` | 顶部 `TimerBar` 冻结只读，下方 `TaskCard` 保留「改简历」、读数 `35:00`、状态 `进行中（暂停） PAUSED`、卡头无旧「回来」链接；`.home-stage` 右上角弹出 `AwayDrawer` |
| **3. 待做卡待开始**<br>（已抽卡 `status: '待做'`，含 `pending`） | 插入临时活动「上厕所」 | 底层仍显示该待做卡（若 `pending` 存在则状态为 `待开始 · 已在计时`，`#f-elapsed` 可改 `pending` 起点；点〔开始〕按 `claim` 结算并收起抽屉）；右上角弹出 `AwayDrawer` | 顶部 `TimerBar` 显示待确认（若 `pending` 存在），下方 `TaskCard` 显示该待做卡；右上角弹出 `AwayDrawer` |
| **4. 待机 / 已暂停**<br>（无进行中活动，或已暂停「学 408」） | 插入临时活动「上厕所」 | 从待机插入：底层保持空白待机（「现在做什么」/ `00:00`）；从已暂停插入：`timerService.insertInTx` 保留原 `resume_entry_id`，底层显示原 `resumeEntry`（「学 408」冻结时长，`进行中（暂停）`）；右上角均弹出 `AwayDrawer` | 从待机插入：`TimerBar` 待机、下方空白卡；从已暂停插入：`TimerBar` 与 `FreeCard`（或 `TaskCard`）显示原 `resumeEntry` 冻结时长；右上角均弹出 `AwayDrawer` |
| **5. 连续插入**<br>（「上厕所」中再点「拿快递」） | 再次插入另一项快捷活动 | `insertInTx` 因前一条是 `'插入'`，保持原 `state.resume_entry_id` 不变；底层卡片继续保持原活动不变，右上角 `AwayDrawer` 切换为「拿快递」并从 `00:00` 计时 | 同左，`TimerBar` 与下方卡片继续保持原活动，`AwayDrawer` 切换为「拿快递」 |
| **6. 临时活动中点 `＋ / 写别的`** | 触发 `beginPending` | `AwayDrawer` 保持打开；底层卡片切为待确认输入态（`待确认 · 已在计时`），`#f-elapsed` 可改 `pending` 起点。输入回车则确认新活动并收起抽屉；点〔放弃〕/ `Esc` 则恢复冻结展示原活动 | `AwayDrawer` 保持打开；`TimerBar` 与下方 `FreeCard` 切为待确认输入态。确认新活动则收起抽屉；点〔放弃〕/ `Esc` 则恢复冻结展示原活动 |
| **7. 抽屉内改读数覆盖 `resumeEntry`** | `#away-elapsed` 调大时长并点〔确定〕 | 部分覆盖：底层读数按最新投影重算；完全覆盖：返回 ID 清空，原进行中卡释放，pending 或另抽出的待做卡仍按 §2.2 显示；均不存在时才显示空白待机，后续点〔回来〕转待机 | 同左，`TimerBar` 与下方卡片遵守同一投影和 pending 优先级 |
