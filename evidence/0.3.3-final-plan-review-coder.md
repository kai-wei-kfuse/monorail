## 范围与决策

1. 仅想法采用标题和可选 Markdown 详情；待办旧多行语义保持。详情页打开笔记窗口、记录条详情草稿转窗，按已确认原型实施。
2. 主线默认 2，保留现有 1–3 可调范围；合法 schema2 旧 1 迁 2，旧 2/3 保留，schema3 用户后来设 1 不重迁。这是满足多主线的技术选择，不称用户指定数量或无限；不改 mainItems，不挤走现有任务。
3. 新增 create_idea、get_idea_details、update_idea、create_task、convert_idea_to_task，共 41 方法（30 写、11 读）。分别覆盖想法创建/阅读/编辑、并存主线创建、标题转明确目标任务；不扩成通用整理、AI 或计划助手。
4. 想法正文单一来源、rawBody 保全、旧全文兼容、内容修订、schema3 备份迁移/旧日志恢复/更新兼容已有明确规则。保留全文读取成本的诚实边界，不把少缓存称为已消除全部 IO。
5. 文档窗单写入、真实来源/epoch、草稿身份和原请求回执、维护取消后正常保存的协议足以指导实施；原型内存映射不作为持久一致性证据。

## 实施约束与验收

- 先按版本流程设 0.3.3，同步基础架构/设计/UI 的窄范围修订及历史，再按 P1–P6 实施。不得把本文当作测试通过记录。
- 复用 createTaskInTx、convertIdeaInTx 和领域建卡/容量来源；现 taskWithItems 的空数组/空事项回退不能成为新严格协议的静默默认。共享规范输入校验与 GUI 映射必须一致，不另写控制器业务规则。
- 成功数据、历史、回执同 journal；原操作重放优先于当前实体，即使后来编辑或删除也不能重建。正文/附件完整保留，不静默截断。
- 实测旧/新版本逐中断恢复、回退备份和原生更新兼容；测试真实窗口关闭/退出/安装草稿保护、原生 QuickBar 交接竞争及持久回执。
- GUI、CLI、MCP、帮助和设置说明同版；真实管道调用后读回，不仅核对工具数量或假传输结果。
- 规模样本验证冷启动/提交/正文打开/查找的 IO、内存与目录增量。不得未测即声称长期积累性能无问题。
- 后端测试沿现 60 秒进程期限，依次定向测试、类型/lint、构建、最小真实冒烟。失败明确记录；用户真实数据只读复制演练。
