## 实现范围

- 仅想法采用单行标题与可选 Markdown 详情：YAML `text` 为标题，同文件 body 为详情；待办保留旧多行文本。`RecordRepo` 常驻摘要，不保留每篇 body/full file text；正文按需读取，每次事务仍做文件读取与哈希检查。
- 内容修订为 `ir3:` 加固定六字段 `{id,text,details_markdown,needs,tags,attachments}` 的 canonical JSON SHA-256；正文先按 N 归一换行。池状态、完成时间与簿记不是内容修订来源。标签从兼容全文提取，不把正文标签搬进标题。
- 旧 v2 想法按 ADR0026 机械映射，原文件备份并对账；v3 写标题/needs或生命周期时保留未改正文原字节，真正详情变化才写归一正文。记录、历史与回执经 journal 提交。
- 主线默认 2，可调 1–3；合法旧1迁2，旧2/3保留，v3主动设置1不重迁；不变更 mainItems，不自动挤走旧任务。
- 详情页可打开已有笔记窗口；记录条想法详情草稿可开窗编辑。相同记录聚焦已有窗口，不同记录可并开；窗口只持草稿，主窗口提交，修订/来源/主会话校验保护跨窗数据。
- 草稿交接绑定草稿ID、版本及操作ID。后来输入不被旧提交清空，原请求重放返回首次结果；后来修改或删除不导致重建。维护检查按目标、请求号和正安全整数 generation 处理；仅取消自身票据。关闭失败保留原注册并明确报错，解除未确认时不继续换目录。
- 正式 Markdown 使用 react-markdown/remark-gfm；不执行 raw HTML，外链只 HTTP/HTTPS，Rust再次检查后打开系统浏览器。窗口无文件写权限。现有笔记入口仅详情页，不含列表开窗按钮、新空白笔记入口或独立项目选择器；窗口不默认置顶。

## 自动化契约与命令

当前 `applicationContracts` 与真实 MCP tools/list 共41项（30写11读）；新增五项：

| 方法 | CLI |
|---|---|
| create_idea | idea create [--title <title>] [--details-file <path> 或 --details-stdin] |
| get_idea_details | idea show <idea-id> |
| update_idea | idea edit <idea-id> [--title <title>] [--details-file <path> 或 --details-stdin 或 --clear-details] [--needs <text> 或 --clear-needs] [--record-revision <token>] |
| create_task | task create --name <name> --slot 主线或支线 [--default-project <name>] [--item <content> ... 或 --items-file <path> 或 --items-stdin] |
| convert_idea_to_task | idea convert <idea-id> (--task-id <id> 或 --new-task-name <name> --slot 主线或支线) (--item <content> ... 或 --items-file <path> 或 --items-stdin) |

新写命令支持已有 `--operation-id`、`--json`、`--agent`。重复 `--item` 接普通文本，结构化 JSON 给 items-file/items-stdin，元素精确为 content/type/timebox_minutes，类型为结果卡/时间盒卡。CLI 的 ID 为位置参数，修订为 `--record-revision`，项目为 `--default-project`。旧 `idea add` 文本为位置参数或 text-file/stdin；没有 idea save/add --text、settings、idea delete、--details、--revision、--include-idea-details 等虚列入口。完整可运行帮助存于 [CLI帮助实证](0.3.3-coder6-cli-help-r8.json)。

旧36方法保持原严格输入/输出及旧多行兼容；新摘要/详情 DTO 独立。公共回执 data 无 windowDoc 全文，规范输入由共享 helper生成；窗口私有草稿身份不改变无附加业务字段时的公共指纹。附件和任务关联等内部实际业务变化参与操作规范，不能拿当前笔记冒充原回执。无自动排计划或开计时。

## 存储评估

保留 [错误标签首轮历史](0.3.3-storage-benchmark-historical-r1.json) 与 [UTF-8修正版](0.3.3-storage-benchmark-corrected-r2.json)。修正版生成器逐篇验证2048/65536/256字节；trueColdStart只指新RecordRepo首次读取，不是整应用冷启动；warmCachedList仍读取文件字节核对。
