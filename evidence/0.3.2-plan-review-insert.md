# 0.3.2 方案审核（显式插入入口，ADR 0024）

审核人 coder-5 · 2026-11-07 · 对象：`docs/adr/0024-explicit-insert-across-windows.md` v1 Proposed，复核 v1.1。需求以 [0.3.2.md](../docs/stages/0.3.2.md) **第 3–5 条**为准。

只读核对需求、状态门槛和 UI 语义。重点：卡/自由暂停、pending 隐藏、输入失焦保留、隐藏撤回。不审 `readSerial` / `viewSeq` / 队列（见 [插入技术侧](0.3.2-plan-review-insert-automation.md)）。未改 ADR / 执行方案 / 代码。

## 结论

第 3–4 条对齐：两种小窗最小按钮、自由计时也给入口、旧 source 自由记录仍切换、待机不是新能力、不为显示单建 MCP。没有「按原文会和已定需求冲突」的阻塞。

四项重点里，pending 隐藏和失焦保留写得清楚。卡/自由暂停、隐藏撤回各有一处不写死实现会和现码拧着。另有一处现有卡头按钮在「隐藏」时仍会因 fallback 露出来。

v1.1 已吸收下方 S1–S3。无新应改。不能写成 GUI 已确认或已开工。

## 应改（v1；已吸收进 ADR 0024 v1.1）

### S1 隐藏入口时必须拿掉 FusedCard 那颗〔插入事件〕，不能 `onInsertEvent ?? writeOther`

- 现状 `FusedCard.tsx:60`：做卡时这颗按钮**总是画出来**，没给 `onInsertEvent` 就走 `writeOther`（换回输入框 / 待确认）。
- ADR 要把 pending / 已插入 / 待机藏掉。若实现只是不传 `onInsertEvent`，待确认时按钮还在，语义仍是「可点插入」。
- 请写死：不可用时**不渲染**这颗按钮（分开布局自由卡/任务卡同理），不要靠回调缺省。
- v1.1：已写死不可用不渲染，并删除 `writeOther` 缺省。

### S2 pending 隐藏是收紧**现有做卡入口**，不要写成只约束新窗

- 现状 `HomePage.tsx:241-242`：待确认时仍可点插入，起点用 `pending.startedAt`，和 0.3.1 已定 67「计时从点下那一刻算」拧着。
- ADR 改成隐藏、先完成或取消待确认、新入口不接纳 pending：比沿用 pending 起点更贴 67，也和第 4 条「方案写清待确认出不出」的决定一致。
- 须标明：做卡卡头一并收紧，不是只藏小窗 / 自由计时。普通输入本身不改，这句保留。
- v1.1：已标明这是对现有做卡卡头的一并收紧。

### S3 「隐藏窗口即撤回」写死范围，避免比已定 67 多一条静默丢字

- 已定 67：Esc /〔回到任务〕才撤回。ADR 给主窗 owner 加了离开首页、隐藏窗口、卸载即撤回。
- 已写名字未回车时，托盘隐藏或最小化会丢掉文本。本产品托盘隐藏是常用路径。
- 请写死：①「隐藏」是否包括托盘隐藏、最小化、被挡住；② 主窗 owner 切到日历/列表是否撤回（按现在那句会）；③ mini 关闭/隐藏=撤回，须在原型上看见。非 owner 的镜像+撤回占用最小按钮那一格，不要再占一块。
- v1.1：托盘/最小化/失焦/切页保留草稿，MainApp 持有主窗表单；显式关闭 mini × 才撤回。

## 核对（四项重点）

### 卡 / 自由暂停

显示门槛（计时中，或暂停且有有效回到目标）与 ADR 0021「卡暂停中也走插入」、第 4 条「自由计时加入口」合得上。「不隐式恢复原计时」「点击之前的待机仍为待机」对。待机 / 宽松没在计时隐藏，对，不是待机直接开始。

现码 `startDraftInsert` 只看 `card.status === '进行中'`。暂停中的卡碰巧仍是进行中，所以卡暂停能进；自由暂停没有 card。实现必须改用「有效回到目标」，不能抄这条 if。

### pending 隐藏

见 S2。休息按钮现已在 pending 时不画（`HomePage.tsx:252`），插入入口与它对齐更一致。

### 输入失焦保留

失焦不提交、不撤回；切分类同一编辑组；Esc / 返回才撤回。对齐已定 67。不复用会 blur 提交的 InlineInput，是小窗这条的关键（现有 mini 名称失焦会写盘）。验证矩阵已列分类点击、IME Enter。够。

### 隐藏撤回

mini owner 隐藏/关闭/重载撤回、主窗隐藏不影响 mini owner、切页不终止 mini 草稿、主窗隐藏可从 mini 走完：这组内部一致，也满足「不为输入唤出主窗」。主窗 owner 的隐式撤回见 S3。已插入 / 插入暂停隐藏入口：对，第 3 条方案项。v1.1 后普通隐藏改为保留。

## 建议

- N1 原事是自由记录时，草稿阶段撤回文案用〔回到原来的事〕（`InsertCard` 已按 `over.kind` 分支）。ADR 写「回到原事」即可，原型不要草稿也写死「回到任务」。
- N2 小窗草稿原地空输入、不落下 InsertCard：第 3 条允许的方案选择，看图确认。
- N3 22×26 + 号无字、放在读数后暂停前：满足「最小按钮」。长名称省略号走原规则，对。
- N4 第 5 条（旧抽卡擦除）不在本 ADR，别卷进来。已单开 ADR 0025。

## 已核对属实

- 第 3 条两种窗口、最小按钮；第 4 条自由计时入口；旧 `mini` / `timerBox` / favorite / recent / continue 自由记录仍切换。
- `explicitInsert` 进 ALWAYS_INSERT，先要求有效原事且没有 pending / insert / rest。
- 草稿未提交不提供暂停 / 结束原事，空名字不能提交。
- taskMode 关闭时自由计时入口仍可用。
- 不为这条新增 MCP / CLI（ADR 0023 的 35 方法不变）。
