## 1. 用户需求与页面内容

页面及文档文案统一采用书面、规范的表述风格，避免口语化表达；页面分为四个分区（`接入概览 / OVERVIEW`、`MCP 配置 / MCP CONFIG`、`CLI 命令 / CLI EXAMPLES`、`前提与排错 / TROUBLESHOOTING`）。

### 1.1 设置入口与可读说明（接入概览 / OVERVIEW）

- 设置中增加独立「AI 与自动化」说明页，编号定为 `09 AI 与自动化（AUTOMATION）`，原 `09 关于` 顺延为 `10 关于（ABOUT）`；包含 MCP 与 CLI 两部分，沿用现有导航、字体、颜色、按钮与滚动方式。
- 用简明书面语言说明：支持 MCP 协议的客户端通过 MCP 接入；具备终端执行能力的 AI 代理、自动化脚本或用户可直接调用 CLI，无需额外经由 MCP 转发。二者共用单轨的能力与本地数据。
- 按四类概述当前已实现的 15 项共享应用方法（须与 `src/shared/application.ts`、`mcp/README.md`、`docs/application/README.md` 真实合同逐项对齐）：状态与回执查询（`get_context`、`get_operation_result`）、想法与待办管理（`save_idea`、`capture_todo`、`find_items`）、计时与临时离开控制（`start_timer`、`start_task_item`、`pause_timer`、`resume_timer`、`stop_timer`、`start_break`、`return_from_break`）、时间统计与记录补录（`get_time_summary`、`list_time_entries`、`add_time_entry`）。不得把后续功能（如任务整理、周回顾）或远程访问说成已支持。
- 说明首次使用须打开单轨并选择数据目录；初始化后，即使关闭主窗口或退出应用，也可在收到请求时按需启动本机后台进程。电脑关机、设备离线或异机访问不在当前支持范围。后台按需启动与 Windows 开机自启是两件事。

### 1.2 MCP 配置（MCP CONFIG）

- 提供默认 stdio 连接方式，使用标准 `JSON.stringify` 生成可复制的 JSON 配置片段（`mcpServers.monorail.command = "node"`、`args = [mcpEntryPath]`）；注明不同客户端可能使用不同的配置文件入口或外层字段格式。
- 使用当前运行应用实际分发的 `monorail-mcp.mjs` 路径，直接复用现有宿主元信息来源，不硬编码开发者用户名、仓库路径、临时测试路径或假定安装目录，不增加第二套路径推断规则。
- 提供「复制 MCP 配置」按钮；含中文、空格或特殊字符的路径作为独立数组元素通过标准 JSON 序列化编码，复制内容可直接使用。
- 默认说明 stdio 模式由客户端按需启动，无需手动先行启动 HTTP 服务。底部以次要说明展示可选本机 Streamable HTTP 启动命令（`& node '<转义后 monorail-mcp.mjs 路径>' --http --port 8765`，监听 `http://127.0.0.1:8765/mcp`），明确需手动启动及仅本机可达，不增加额外验收前置。

### 1.3 CLI 示例（CLI EXAMPLES）

- 展示当前安装版 `monorail-cli.mjs` 的真实路径和可复制命令，说明其为自包含执行包、直接通过 `node` 调用，无需先构建源码。
- 提供 6 条独立完整的常用命令示例（每条单独展示并配独立「复制」按钮）：读取当前上下文与待处理通知（`context --json`）、保存想法记录（`idea add ... --json`）、查询今日时间统计（`time summary --day today --json`）、开始自由活动计时（`timer start ... --json`）、停止当前计时（`timer stop --json`）、查看命令行帮助（`--help`）。
- 复制文本采用安全的 Windows PowerShell 参数引用生成函数（统一使用单引号 `'...'` 包裹参数并将内嵌单引号 `'` 加倍为 `''`，防止路径或参数含空格、中文、`$`、反引号时发生插值或截断，并通过单元测试与实机执行验证）。
- 示例与真实 CLI 参数合同严格一致，说明 `--json` 输出结构化 JSON 供程序与 AI 解析。页面示例不执行写入，复制按钮只复制文本。
- 不把未实现的全局 `monorail` 命令、PATH 注册或一键安装说成现有能力；本次不新增这些功能。

### 1.4 前提与排错（TROUBLESHOOTING）

- 清楚列出 Node.js 24 运行要求，以及“客户端提示找不到 `node`”时执行 `node -v` / `where.exe node` 检查安装、重启客户端刷新进程环境变量或改填 `node.exe` 绝对路径的操作建议（与真实运行要求一致）。
- 覆盖首次未初始化（`SETUP_REQUIRED`）、配置或已登记入口路径失效（`CONFIG_CORRUPTED`）、后台启动失败或状态未就绪（`STARTUP_FAILED` / `UNAVAILABLE`）、待确认状态或计时状态已变化（`PENDING_CONFIRMATION` / `STATE_CHANGED`）、连接中断结果未知（`RESULT_UNKNOWN`）等常见问题；给出与现有 `src/shared/appError.ts` 及 `client/pipe.ts` 错误语义严格一致的下一步处置方式，不自动重试写入。
- 告知 AI 操作会真实修改本地记录与计时状态；仅说明目前实际支持的边界，不新增授权开关、权限系统或安全承诺。
- 复制成功有明确反馈，失败明确显示；不能把失败当成功。若无法取得实际路径或文件不存在，应明确显示错误状态并提供解决步骤，同时禁用复制按钮，不能用猜测路径替代。

## 2. 实现边界与线索

保持共享应用接口、MCP/CLI 并列、桌面唯一写入者及 journal 不变量；本次属于说明页面与配置展示，不重写协议、业务或更新状态机。不改变数据 schema、默认主题、开机自启、Beta 渠道偏好或已有 15 项应用方法。

- `docs/application/README.md`、`mcp/README.md`、`cli/commands.ts`：命令和配置的现有合同。

路径必须来自运行时实际安装信息，优先复用现有元信息来源；如需新增读取展示信息的原生命令，保持只读并补命令权限。不得把原生/Node 依赖放入 shared 纯契约层。不要引入第二份业务方法注册表；能力介绍可以人工编写用户文案，准确对应现有实现。
