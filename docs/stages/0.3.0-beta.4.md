### 1.2 小窗口 / mini 窗口：选分类与输入时的历史记录（D1，原型已定稿，待统一开发）

1. **现状**（代码核对，2026-11-05）：
   - 两种窗口都由 `src/app/MiniApp.tsx` 渲染，布局在 `src/app/shell/MiniWindow.tsx`；`mode = 'tiny'`（mini 窗口，320×46）隐藏了「记到 项目」这一行。
   - 小窗口（520×88）已有分类选择：「记到」后面是 `ProjectPicker flat`（`MiniApp.tsx` 的 `meta`），选了立即改正在计的条目或卡（`editOpen` / `editCard`）。但只在有正在计的事时出现；待机、待确认（刚点名称开始写）时这一行显示「没有在做的事」，写新事件时选不了分类，只能在名称里写 `@项目`。不能在小窗新建分类。
   - mini 窗口完全没有分类选择，只能写 `@项目`。
   - 两种窗口点名称就地变成输入框（`InlineInput`），没有任何自动完成。主窗口的自动完成是 `src/pages/home/Suggest.tsx` + `suggestions.ts`：收藏（计时条的预设，不限条数）、待做的卡（最多 4 张）、最近的记录（按开始时间新到旧，同名只留最新，去掉待机 / 休息 / 睡眠，最多 5 条）；按输入不分大小写筛选，没写字时全列。只在写新事件时出现，改正在计的那条时不出现；只能用鼠标点。选中后直接开始：收藏 → 按预设开始；卡 → 开始这张卡；最近的记录 → 「继续」，照抄描述、项目、标签另起一条，起点用待确认的起点。
   - 小窗快照（`MiniSnapshot`）现在只带 `projects` 和 `knownTags`，没有收藏、待做的卡、最近的记录；小窗命令也没有「按收藏 / 卡 / 最近的记录开始」。
   - 小窗里的改动已经按 beta.3 操作历史记为「手动 · 小窗」（`mini.*` 动作）。这里说的「历史记录」指上面的输入自动完成，不是操作历史。
2. **用户确认（2026-11-05）**：
   1. mini 窗口的分类放在名称右边（方案 A）：常驻一个带色点和分类名的小块，点开下拉切换。待机时不显示。
   2. 小窗口写新事件（待机点名称开始写）时，「记到」也显示并可先选分类，回车后记到所选分类；名称里写了 `@项目` 时以名称里的为准（同主窗口 `useEntry`）。
   3. 不加标签选择。
   4. 历史记录完全照主窗口：收藏 / 待做的卡 / 最近的记录三组，筛选与条数规则同 `suggestions.ts`；只在写新事件时出现，改正在计的那条时不出现；选中即开始（收藏按预设开始、卡开始这张卡、最近的记录「继续」）；只能鼠标点。
   5. 弹层自适应：下面放得下就往下展开；放不下且上面空间更大时翻到上面，窗口向上变高、小窗本体在屏幕上不动；高度不超过所选一侧剩下的屏幕工作区，超出滚动；收起后窗口恢复原来的高度和位置。

### 1.3 想法池加「已完成」按钮（D2，已确认交互，原型待确认）

1. **现状**（代码核对，2026-11-05）：
   - 想法池在「背包 → 02 想法池」（`src/pages/backpack/IdeaPool.tsx`）。每行只有两个按钮：〔转成任务〕（已转的想法变灰显示〔已转〕）和〔删除〕（二次确认后永久删除文件，没有回收站）。没有编辑、没有手动进冷库、没有状态筛选；列表只列活跃池和已转任务，冷库不在这里显示。
   - 想法的状态是记录上的 `pool`：`活跃池 / 冷库 / 已转任务`（`src/data/schemas.ts` 严格枚举）。没有「已完成」。已转任务的想法灰显、不占上限、不进擂台、不过期。活跃池的想法约 60 天（`ideaExpireDays`）没动过自动进冷库；每周回顾有擂台（超上限时两两对决）和冷库捞取。
   - MCP / CLI 只能保存想法（`save_idea`），`find_items` 输出的 `pool` 也是这三个值的严格枚举。
   - **退回 v0.2.5 的兼容**：v0.2.5 的 `pool` 也是同样的严格枚举，并且每次事务都读全部记录。如果新增一个 `pool` 值（如「已完成」），用户退回稳定版 v0.2.5 后所有写操作都会失败，要么升数据格式版本、要么改成不增加枚举值的存法（另加一个 v0.2.5 会原样保留的字段）。具体存法写进方案和 ADR。
2. **用户确认（2026-11-05）**：
   1. 「已完成」= 这个想法本身已经做到了，不用再转成任务。
   2. 点了以后收进想法池里的「已完成」列表（不在想法池列表里显示）。
   3. 能撤销，撤销后回到想法池。
   4. 已转任务的想法没有这个按钮。
   5. 不用二次确认。
   6. MCP / CLI 也能标记完成。
   7. 退回稳定版 v0.2.5 时，已完成的想法在 v0.2.5 里显示成冷库里的想法，数据不丢；v0.2.5 的每周回顾可能把它当冷库想法拿出来捞。用户可以接受（之后会发 0.3.0 稳定版）。
3. **原型（待用户看截图确认）**：`../原型/页面/idea-done-prototype.html`（单文件，新增类名 `id-` 前缀），截图 `../UI参考截图/v0.3.0-beta.4-idea-01..05-*.png`。原型里的取舍：
   - 想法池上方加分段〔想法池 N | 已完成 N〕（与列表页〔计时记录 | 操作历史〕同一种分段），筛选框两边共用；左侧导航「想法池」的数字仍是活跃池条数。
   - 想法池每行按钮改为〔转成任务〕〔✓ 完成〕〔删除〕；已转任务的行仍是〔已转〕〔删除〕。按钮文字用「完成」（动作），列表名叫「已完成」（状态）。
   - 点〔完成〕后这一行从想法池消失，右上角提示「已完成「…」，收进「已完成」；在那里可以撤销」。
   - 「已完成」列表按完成时间新到旧，每行：前面一个勾、正文、标签、「完成于 今天 10:12」和谁标的（手动 / MCP · 调用方 / CLI · 调用方，沿用操作历史的调用方显示），按钮〔撤销完成〕〔删除〕。空列表提示「还没有完成的想法。想法池里做到了的，点〔完成〕就收到这里。」
   - 已完成的想法不占上限、不过期进冷库、不进擂台和冷库捞取。撤销完成算一次「动过」（重新从 0 天计）；池子满了也能放回，下次回顾时用擂台压回上限（沿用「池子允许暂时超过上限」）。
   - 面板说明加一句「已经做到了的点〔完成〕，收进「已完成」，不占上限，也不会进冷库。」
4. **开发影响（预估，待方案和 ADR）**：存法不增加 `pool` 枚举值（v0.2.5 读不了新值）：已完成存成 `pool: 冷库` + `cold_since` + 新字段（如 `completed_at`，v0.2.5 原样保留），本版按新字段区分冷库与已完成；需要审一遍所有读 `冷库` 的地方（过期、冷库捞取、擂台、`find_items`）。新增操作历史动作（完成、撤销完成）。共享应用接口新增「标记想法完成」写方法（MCP 工具 + CLI 子命令，带 `operation_id` 重试），`find_items` 的想法状态要能表示已完成（接口约定变更）；撤销完成是否也开放给 MCP / CLI 未定（原型只做了界面上的撤销）。
