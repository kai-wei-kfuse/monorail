# 0.3.0-beta.4（需求收集中）

版本 v1.6 · 2026-11-05 · 状态：需求收集中。D0 版本同步已做；D1（小窗选分类与输入历史记录）原型已定稿；等待下一项需求；未开始开发。未发布、未覆盖日常版。

## Current Plan（v1.6）

沿用 beta.3 的做法：用户提出的需求先逐条写入本文件，收齐后制定执行方案（必要时加 ADR）、经审核再统一开发与验收。上一版 `v0.3.0-beta.3` 已发布到 Beta 渠道（[发布总结](../../evidence/release-0.3.0-beta.3/summary.md)），其未测项见下方「beta.3 遗留」，是否并入本版由用户决定。

当前已收集的 `0.3.0-beta.4` 需求清单：

1. **小窗口和 mini 窗口都能选分类；在两种窗口里输入事件时，也弹出和主窗口一样的「历史记录」自动完成（收藏 / 待做的卡 / 最近的记录）；mini 窗口去掉「×」、读数改小**（v1.1 记录；v1.6 原型定稿 `../原型/页面/mini-prototype.html`、截图 `../UI参考截图/v0.3.0-beta.4-mini-01..13`；待需求收齐后统一出执行方案）。

## 1. 范围与要求

### 1.1 版本同步（D0）

使用 `npm run version:set -- 0.3.0-beta.4` 将版本清单同步至 `0.3.0-beta.4`，`npm run version:check` 通过。

### 1.2 小窗口 / mini 窗口：选分类与输入时的历史记录（D1，原型已定稿，待统一开发）

1. **现状**（代码核对，2026-11-05）：
   - 两种窗口都由 `src/app/MiniApp.tsx` 渲染，布局在 `src/app/shell/MiniWindow.tsx`；`mode = 'tiny'`（mini 窗口，320×46）隐藏了「记到 项目」这一行。
   - 小窗口（520×88）已有分类选择：「记到」后面是 `ProjectPicker flat`（`MiniApp.tsx` 的 `meta`），选了立即改正在计的条目或卡（`editOpen` / `editCard`）。但只在有正在计的事时出现；待机、待确认（刚点名称开始写）时这一行显示「没有在做的事」，写新事件时选不了分类，只能在名称里写 `@项目`。不能在小窗新建分类。
   - mini 窗口完全没有分类选择，只能写 `@项目`。
   - 两种窗口点名称就地变成输入框（`InlineInput`），没有任何自动完成。主窗口的自动完成是 `src/pages/home/Suggest.tsx` + `suggestions.ts`：收藏（计时条的预设，不限条数）、待做的卡（最多 4 张）、最近的记录（按开始时间新到旧，同名只留最新，去掉待机 / 休息 / 睡眠，最多 5 条）；按输入不分大小写筛选，没写字时全列。只在写新事件时出现，改正在计的那条时不出现；只能用鼠标点。选中后直接开始：收藏 → 按预设开始；卡 → 开始这张卡；最近的记录 → 「继续」，照抄描述、项目、标签另起一条，起点用待确认的起点。
   - 小窗快照（`MiniSnapshot`）现在只带 `projects` 和 `knownTags`，没有收藏、待做的卡、最近的记录；小窗命令也没有「按收藏 / 卡 / 最近的记录开始」。
   - 小窗里的改动已经按 beta.3 操作历史记为「手动 · 小窗」（`mini.*` 动作）。这里说的「历史记录」指上面的输入自动完成，不是操作历史。
2. **用户确认（2026-11-05）**：
   1. mini 窗口的分类放在名称右边（方案 A）：常驻一个带色点和分类名的小块，点开下拉切换。待机时不显示。
   2. 小窗口写新事件（待机点名称开始写）时，「记到」也显示并可先选分类，回车后记到所选分类；名称里写了 `@项目` 时以名称里的为准（同主窗口 `useEntry`）。
   3. 不加标签选择。
   4. 历史记录完全照主窗口：收藏 / 待做的卡 / 最近的记录三组，筛选与条数规则同 `suggestions.ts`；只在写新事件时出现，改正在计的那条时不出现；选中即开始（收藏按预设开始、卡开始这张卡、最近的记录「继续」）；只能鼠标点。
   5. 弹层自适应：下面放得下就往下展开；放不下且上面空间更大时翻到上面，窗口向上变高、小窗本体在屏幕上不动；高度不超过所选一侧剩下的屏幕工作区，超出滚动；收起后窗口恢复原来的高度和位置。
3. **原型（待用户看截图确认）**：`../原型/页面/mini-prototype.html`（单文件，新增类名 `mp-` 前缀），参考截图 `../UI参考截图/v0.3.0-beta.4-mini-01..09-*.png`。原型里的取舍，需用户确认：
   - 两种弹层（历史记录和分类下拉）都贴着小窗、和窗口一样宽。现行小窗口的分类下拉是 168px 宽的浮层，窗口变高后两边露出黑底；改成同宽后也一起改。
   - mini 窗口 320 宽时名称只剩约 3 个字（截图 03）；拉宽窗口（最宽 520）能看到更多（截图 09，420 宽）。分类块最宽 72px，长分类名省略。
   - 计时中的是卡时，改分类改的是卡（沿用现行小窗口）。小窗里不新建分类。
   - v1.3 用户要求：mini 窗口去掉关闭「×」，读数字号从 20px 改为 16px；320 宽时名称约能显示 5 个字（截图 03）。关 mini 窗口改用主窗口底栏「关闭小窗口」、主窗口里按 M 或托盘。小窗口（520×88）的「×」和字号不变（按 mini 窗口理解，待用户确认）。第 1 稿截图移到 `../UI参考截图/v0.3.0-beta.4旧/第1稿/`。
   - v1.4 用户要求：mini 窗口的分类块靠近右边黑块，有分类块时左区右内边距 12px → 4px（待机没有分类块时不变）。第 2 稿截图移到 `v0.3.0-beta.4旧/第2稿/`。
   - v1.5 长分类名（演示「英语口语练习打卡计划」，项目名本身不限长度）：mini 窗口分类块最宽 72px，只显示「英语口…」，320 宽时名称也被挤到约 3 个字（截图 10）；拉到 520 宽分类块仍是 72px（截图 11）；完整名字在悬停提示和下拉里（截图 12）。小窗口「记到」一行能放下完整名字（截图 13）。第 3 稿截图移到 `v0.3.0-beta.4旧/第3稿/`。
   - **v1.6 用户确认原型（「ok，就这样定」）**：按截图 01–13 现状定稿，分类块固定最宽 72px、不随窗口放宽（按「就这样」理解为维持现状，用户如指的是放宽方案再改）。`../UI风格规范.md` §7.4 / §11.9 尚未同步，归入执行方案的第一步。
   - 用户确认原型后，同步 `../UI风格规范.md` §7.4 / §11.9，再写执行方案。
4. **开发影响（预估，待方案）**：`MiniSnapshot` 增加自动完成数据（收藏、待做的卡、最近的记录）；小窗命令增加按收藏 / 卡 / 最近的记录开始，走主窗口同一套 service，操作历史来源记「小窗」；写新事件时 `editOpen` 带所选分类；`MiniApp` 的窗口尺寸逻辑改为按屏幕剩余空间决定弹层方向，向上展开时同时移动窗口位置（Rust 侧 `resizeMiniWindow` 需要支持改位置，或新增命令）。不改数据格式。
