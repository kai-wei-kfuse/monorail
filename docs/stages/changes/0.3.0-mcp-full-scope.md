## Stage Change Proposal

状态：Accepted v1.2，依据用户授权与 coder-3 v2 无阻断复审。2026-11-03。

版本归属修订 v1.4：用户最终确定 MCP 为 **0.3.0**，当前计划为 `../0.3.0.md`，执行交 coder-3；v1.3 的 0.2.6 归属仅保留历史。

### Problem
现行 0.3.0 仅包含保存想法原型；用户完整需求还包括今天的时间分析、计时控制和通用 MCP 客户端/个人 Agent 接入。官方 SDK 已进入 v2 稳定线，现实现仍在 v1。

### Why It Matters
直接扩展现原型会遗漏协议版本、写入重试、桥接生命周期和远程可达性；需要先明确整体验收。

### Options
1. 发布当前仅保存原型，其余另开阶段。
2. 0.3.0 完成本机功能与双传输兼容，再独立交付异机部署。
3. 将云端网关/设备服务全部纳入同一版本。

### Decision
采用选项 2；完整调研与任务表见 `../../../evidence/mcp-execution-plan.md`。Current Plan 已更新至 v1.2，架构决定见 ADR 0009。

当前决定（v1.2）：以 `../../mcp/requirements-and-design.md` 的 v2.1 为准；0.3.0 扩展里程碑映射 M4–M9，增加按需后台启动、低价模型验收以及首批查找/待办/临时活动/补录能力。任务整理与移动同步独立列为后续，保留原型 M0–M3 记录。

### Impact
影响 SDK、共享工具契约、写入结果回执、计时状态校验、统计服务、发行与兼容验收；涉及新增数据实体时须有 ADR 与迁移/恢复设计。保留现有业务模型和单写入者。
