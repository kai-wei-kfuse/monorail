状态：Accepted v0.4 · 2026-11-08。唯一维护方：coder-6。coder已完整审核执行方案v0.5、范围v0.4与ADR0026 v0.5/0027 v0.2/0028 v0.3/0029 v0.1，正式放行coder-3实施。已审范围与契约不变，最新流程覆盖原两待答/全员前置门槛；实现完成后仍需复审。

审核：[0.3.3-final-plan-review-coder.md](../../../evidence/0.3.3-final-plan-review-coder.md)；Runner `01M6WSEHW6ZX6YECSPYQEFV4CJ`。本次只标Accepted并引用审核，不变更阶段范围。

### Problem

用户指定0.3.3：想法先写标题，详情可选、支持Markdown、长段落与链接；CLI/MCP同能力；检查数据增长；主线不要限制只能一个。原始流程见Runner `01M6VKXNVCV97XWYPZM9YSR5MQ`；最新用户确认和新指令（`01M6WQPHN8EDD2JA3ZSM57YDWN` / `01M6WQPHQKEA5KZ7298QE2CJ2N`）明确coder-6定稿→coder审核放行→coder-3实施→coder-6与coder审核，原流程的全员前置门槛已被替代。

用户新增：可以新开一个大窗口打开想法笔记（`01M6WJD888ATZHPB8C4RB8MZEN`）。[ADR0028](../../adr/0028-idea-document-window.md)补同记录聚焦/不同记录并开、main写入、修订/epoch、草稿关闭/更新/退出；常规交互推荐待原型，不另加范围审批。

用户已确认的最新原型细节：已有笔记新窗口按钮仅详情页、列表去掉；窗口名“单轨 · 想法笔记”；快速记录条展开“写详情”后可选择独立窗编辑未保存想法；独立窗去掉多余外标题栏/外边距壳，编辑框贴边铺满且全部直角。早先局部反馈与最终原型确认分别保留出处，不把最终确认写成仍待。

现有 `save_idea` 已支持多行，不是存储只能一行。缺的是标题/详情语义和相应界面。`QuickBarApp.tsx:20` 把 text 写入 YAML 和 body；`commit.ts:287-288` 在 text 变化时覆盖 body。旧正文不能假定为空。每次提交还会全量读取记录，长文不应被塞进列表、快照和所有事务。

正式代码目前mainTasks默认1/可设1–3，mainItems默认5。原型有并列主线但未实际交付数量设置，待办无Markdown详情；本稿按主审要求只做想法Markdown、推荐新默认2/旧1迁2/旧2和3保持且沿现1–3范围，不再重复问原两题。数量是最小推荐，不称用户指定2或无限；原型演示5条与保留max3的差异明确见ADR0027，供主审最终核对。

### Why It Matters

这涉及持久格式、旧数据、跨 GUI/CLI/MCP 契约和领域容量规则，是结构性改动。只加文本框或改一个默认值会留下正文覆写、既有设置仍为 1、接口不能编辑和长文重复装载的问题。

### Options

| 方案 | 得失 | 当前判断 |
|---|---|---|
| 长详情仍放 YAML text，UI 展开显示 | 少改格式，但列表/事务/回执继续拿整段内容，标题与详情不独立 | 不推荐 |
| text 作标题、body 作详情，保持 schema2，只写降级警告 | 新版可正常工作，但 0.3.2 改标题会覆盖详情 | 需明确承担直接降级破坏风险，不宣称兼容 |
| 明确标题/body 语义、最小迁移并升 schema3 | 旧版会解析拒绝（不承诺友好提示），journal仍先恢复；备份回退及原生兼容联动 | 已获coder最终审核Accepted，迁移实测仍属实施验收 |

### Current Decision（Accepted v0.4）

第三项已获最终审核：想法text作标题、body作详情，固定映射首LF/不同正文保留，标签从完整内容派生；新create_idea/get_idea_details/update_idea复用同内容服务，旧save/find/complete/reopen全文语义保持。本版待办不加Markdown详情，不改旧多行或Card.content。

新增[ADR0029](../../adr/0029-v033-automation-parity.md)：将三项内容方法及create_task/convert_idea_to_task同版开放CLI/MCP，目标41方法（30写11读，送审源码基线36项）。任务创建只映射并存主线；转换只映射已确认标题转明确主线/新任务，原记录详情完整保留，类型/分钟沿现卡模型。长文文件/stdin、显式patch/修订、容量/原回执、工具说明与CLI帮助/设置说明同版；不补整套历史整理、AI或自动排计划。

每次事务仍读记录字节核哈希，摘要不缓存Entity.text整文件/Entity.body；详情在明确查询/已打开窗口持有。不是“正文从不读”或全量IO已消除。has_details与修订从真实最终body同提交派生。迁移完整journal先写state3，旧Journal先补完再解析拒绝的路径逐点实测。

D2固定原文件/body字节哈希与N语义修订分开；仅标题/needs/生命周期与相同详情patch保留原body字节，实际详情改动/创建/迁移才规范化。D1检出未存稿先取消维护并确认原生解除，再恢复编辑/常规保存，用户重触发后重新完整检查，不在冻结队列等保存。

QuickBar草稿交接是该新窗口能力的一部分：draft_id/version/快照、local/saving/handoff/create_pending/committed同一状态决定路由；已交接草稿两端统一main创建与持久回执，普通未交接create_new保留。先行快存结清真实record_id，未知不重复建；首次创建后只编辑同一记录，原条后写保留。此为基础架构§3.2窄桥例外，接受后同步原文/修订历史，不改为通用QuickBar文件编辑权限。

主线[ADR0027](../../adr/0027-multiple-main-tasks.md)固定最小推荐和精确settings迁移，2→3与想法迁移同journal，schema3用户主动设1不重迁，坏文件/缺mainTasks明确报错、未知字段保留、不挤走现任务。容量统一canAddTask与itemCapacity，不能只改defaults留下旧1门槛。
