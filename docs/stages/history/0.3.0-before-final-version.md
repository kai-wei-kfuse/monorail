## Superseded Plan（原 Current Plan v1.2）
按用户扩展需求与 coder-3 的 v2 无阻断复审，采用 [需求与设计](../mcp/requirements-and-design.md)、[范围变更决定](changes/0.3.0-mcp-full-scope.md) 和 [ADR 0009](../adr/0009-mcp-expanded-capabilities.md)。0.3.0 目标为本机通用 MCP、按需后台启动、低价模型友好的记录/查找/时间查询与计时工具。具体任务见 M4–M9。首批核心目录按用户场景分组，并不将表格行数当作最终工具数量。

公共文件 package.json、锁文件、bootstrap、原生 handlers/capabilities 的变更归主代理；保留已有 CLAUDE.md、版本开发流程及 journal-real.json 改动。新增 receipt 存储与后台启动按对应里程碑落实细节和验证；不能把原型阶段“不新增格式”的约束误套到扩展阶段。手机同步与异机部署列为后续，不宣称已支持。

### 任务与验收
以下 M0–M3 为已完成原型历史，仅代表 save_idea 的原型证据，不代表扩展设计已实现。
- [x] M0：确认现有模型和事务入口，形成 ADR 与范围。
- [x] M1：实现 save_idea、stdio MCP、Windows 管道和主窗口服务接线。
- [x] M2：454 项应用测试、类型/lint、MCP 类型与协议冒烟、前端/正式配置原生构建通过；真实 SDK Client 调用隔离原生应用并核对 Markdown、journal 和计时状态通过。
- [x] M3：mcp/README.md 提供客户端配置和调用过程；evidence/0.3.0-mcp.md 记录验收边界。实际聊天宿主配置与界面点击验收尚未执行。
- [ ] M4：锁定官方 SDK v2 工厂接口，验证 stdio/HTTP 对两代协议客户端的实际兼容；同步检查链。
- [ ] M5：同 journal 回执、幂等命中零写入、提交后告警、宿主生命周期、按需后台启动；首次未配置/恢复失败可查询，主窗口不闪现。
- [ ] M6：get_context、查找/待办捕捉和时间查询；使用累积未处理通知；统计区分非待机、待机、空档并核对时区/活动日。
- [ ] M7：普通计时、指定待办、临时离开/回来、补录；共用领域前置检查，修复暂停后停止，核对待机插入后回来。
- [ ] M8：stdio 默认与显式本机 HTTP、自包含分发包、安装路径定位及传输检查，脱离源码树可运行。
- [ ] M9：至少两个独立真实客户端与低价模型行为评测；记录实际成功/错误、tokens/轮次/延迟，不以 SDK 自测替代模型验收。
- [ ] 发布与安装：不由本轮自动执行。

验证与交接：../../evidence/0.3.0-mcp.md。版本在开发起始同步到 0.3.0，不代表发布。

设计复审：[coder-3 v2 结论](../../evidence/mcp-execution-plan-review-v2.md)。设计通过，M4–M9 尚未实施；下一步从 M4 开始。四条实施建议已纳入需求文档 §5.4 和对应里程碑。
