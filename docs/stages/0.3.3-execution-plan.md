这是结构性改动：持久格式、内容来源、事务正文、API、查询/投影、容量规则与数据兼容一起受影响。最小 UI 补丁会保留正文覆写和原默认主线限制；采用同源内容读写、迁移保护、按需详情和统一容量。

用户已确认：想法标题+可选长Markdown详情与链接、阅读/编辑、GUI与CLI/MCP同能力、多主线、新窗口打开想法笔记及快速记录条详情草稿转窗。已有笔记开窗按钮只在详情页，不在列表；窗口名“单轨 · 想法笔记”；独立窗移除多余外标题栏和外边距壳层，编辑框贴边铺满、全部直角。仅想法有Markdown详情，待办多行能力保留。数量策略是团队最小推荐，不虚称用户指定2条/无限。

技术完整性：不丢旧/未提交内容、改标题不盖详情、旧多行后半截默认仍可查、多个入口同写入/修订、主窗是业务写入者。它们不需另请用户批准才能成立。

已确认原型路径：标题快存、点行阅读/编辑、列表标题轻标记、转任务预填标题且完整保留原想法详情；同记录复用聚焦、不同记录并开大窗。主线子项上限不默认变化。原型数字/内存幂等/自动inToday不提升为正式承诺，数量选择与服务不隐式排计划/开计时见ADR0027/29。

### 内容与 API 技术决定（Accepted v0.5）

- 标题唯一存 YAML `text`，详情唯一存同一文件 Markdown body；业务摘要对象不带全部详情。新 API 用 title 字段时只是边界映射，不再持久化另一份 title。
- 选择新增 create_idea/get_idea_details/update_idea 三方法，不做旧method union。旧 save_idea/capture_todo 的必填和输出形状/完整多行语义保持。精确输入、DTO、兼容拼接C、CLI命令与样例以ADR0026“内容格式与API”为单一规范。
- 同版再补create_task/convert_idea_to_task，目标41方法（30写11读）。两项只映射并存主线创建/原型标题转指定任务；公开输入输出、容量、原回执与CLI事项JSON以ADR0029为单一任务操作契约，不补整套历史整理能力。
- 旧 save_idea 的 `看视频\n稍后看 https://example.com/a\n#服务器` 回执仍返回整段text；新存标题“看视频”、详情保留首LF；find_items查“稍后看”仍命中并返回兼容全文。旧 capture_todo 的完整Card.content不拆走；complete/reopen旧text结果同样不缩首行。
- get_idea_details返回完整IdeaDocument，新create/update回执只返回IdeaSummary，避免receipt.data再复制长文或每次改标题回显未改正文；input仍完整保留，不加截断。正文型记录保存门同时检查title/details/attachments；新建缺省空、编辑省略保持/空串清空；正文仅换行规范化。
- record_revision固定为ADR0026所列{id,text,details_markdown,needs,tags,attachments}规范JSON的SHA256不透明令牌；排除池/完成/时间/簿记/主窗epoch。不用timer expected_state代替。来源epoch另用于独立窗口。
- CLI旧idea add仍是save_idea；新idea create --title/--details-file(或stdin)、idea show、idea edit --record-revision。重放只恢复原record_revision，不覆盖本次正文参数；规范update只含实际patch，省略不是空串。
- 写入仍用 operation_id、规范输入、持久回执和历史。重放优先于当前状态检查；同 ID 改标题/详情/修订必须冲突；结果未知按原 ID 查回执。CLI 重试恢复原技术字段但保留本次业务参数参与冲突校验。
- find_items默认按兼容全文C+tags+needs匹配并返回旧text单字段，不丢旧后半截。正文仅在该明确查询生命周期持有，成本实测；不做全文索引库、不把它常驻提交缓存。原型/GUI“标题、标签、需要”筛选是单独明确的简洁口径，不能拿它改变旧API默认全文语义。
- 标签迁移保留已有数组，不抬进标题；实际标题/详情改变时以C调用现extractTags，代码不新增特殊排除、URL片段/Markdown标题按现规则处理；仅needs/状态/簿记/noop不重抽。全文参与避免仅改标题后丢非首行#标签。
- has_details=最终body.length>0派生，不在YAML存第二份；摘要不能留Entity.text整文件。正文only变化在compare.ts记录字段表按digest比较并写“详情已更新”，首60字相同也能记，全文不进历史。记录/标签/历史/回执同journal。
- 本版待办不增加Markdown详情；capture_todo完整多行与Card.content原行为保留，不把想法详情复制到cards body。
- D2以ADR0026“原始字节与语义换行”为准：外改用原文件/body字节哈希，内容修订/历史用N语义。记录专用读取先拆原frontmatter边界，保留写目标rawBody；标题/needs/生命周期与语义相同详情patch不重写body，实际详情变化/创建/迁移才写N。不使用目前decode归一后的body冒充原字节，补Windows原生UTF-8/CRLF验证。

### UI、草稿和外链接线（v0.5）

快速记录条的想法默认单行标题：Enter保存；“写详情”或标题Shift+Enter展开详情并聚焦；详情Enter换行，保存按钮/Ctrl+Enter提交全部实际字段；Tab保留焦点导航。沿已确认原型提示实现，IME选字Enter不提交。待办保留原多行输入/Shift+Enter换行，不复用想法展开快捷键。

编辑/预览/展开只控制显示，不决定保存值；收起详情后保存仍带已填正文。想法/待办分开保留草稿，类型切换不把想法详情提交成待办。保存只重置已保存类型，其他草稿仍保留。

想法详情展开区增加“去独立窗口编辑”，不提前落盘。草稿有draft_id、draft_version和移交快照，未创建时不造record_revision；原条后写必须保留。ADR0028定义local/saving/handoff/create_pending/committed状态：仅已交接草稿的原条/大窗首次创建统一main的create_idea与持久回执，普通未交接quick_save仍为既有旁路。交接先结清已接纳快存的原record_id，未知不另建；原条/大窗的原create重试保持同请求，异内容拒绝，创建后编辑走update_idea。原型内存map不算正式幂等保证。

dirty比较所有实际草稿与其基线（标题、详情、needs/任务等元数据、附件），而非只看当前显示或trim后标题；收起/隐藏/切类型不清dirty。更新检查读真正草稿，只有详情、空标题、无附件也要阻止丢稿。编辑器按可用屏幕高内滚，不截断。

想法池点行打开记录；阅读态默认 Markdown、可转编辑；链接仅独立点击打开文中现有 http/https，不能同一点击既展开又跳走。标题及正文修改后，列表/详情/完成列表一致，详情不出现在当前计时卡上。Markdown 标题/代码不得被当成计时命令。

正式使用react-markdown+remark-gfm，不启用raw HTML执行；危险URL不可点击，原文保存不清洗。新窄open_external_url由app注入platform，Rust用url再次校验http/https后开系统浏览器；lib/build commands、main/quickbar/idea-window capability同步。不开应用内浏览、不抓网页/视频。原型小渲染器不搬进app。

窗口关闭给保存/放弃/取消；冲突/失败/未知结果不清稿。main隐藏仍处理保存，重载旧epoch不写。安装更新扩现QuickSaves检查main、quickbar、全部笔记窗；沿pauseCommits、不另建业务写锁。D1检出dirty/未知/检查失败先取消本次维护并确认原生状态解除，再恢复提交准入/编辑并聚焦常规保存；用户重触发才重新完整检查，绝不冻结中等保存或给旁路权限。检查未ready/关闭/失联不假clean、可取消等待；tray真正退出也接同草稿保护，不能直接app.exit丢笔记。具体身份/取消顺序见ADR0028。

### 存储与性能评估（v0.5）

不能用“1000×2KB≈2MB”证明总体没问题。分开量：正文+YAML+附件、文件数量/元数据；读取缓存和事务克隆；永久 receipts 全文副本；180 天历史（现有参数摘要规则）；当次 journal 改前/改后；一次迁移备份。

本版基线只调整 records：每次事务仍枚举/读取文件字节以核对真实哈希和新 QuickBar 文件；缓存和事务只保留 metadata、详情标记和原哈希，不留每篇全部正文。只有详情/内容查找/写目标持有对应全文。只省解析/缓存/克隆，不把哈希称成不读文件；mtime:size 相同也可能外改。

新读法用真实摘要类型，不造body=''的伪Entity。写目标读真实Entity并比较本事务原哈希；QuickBar新文件当次解析、补历史和物化，不等打开详情。摘要是派生内存，不独立持久化，不提前更新未提交值；journal后投影失败时磁盘已经变，后续须重新从磁盘计算。主审最终通过该数据流后实现，再交coder-6/coder审代码证据；基于可靠变更事件跳过文件IO不进入本版默认范围。

has_details/record_revision来自同一最终metadata+body，提交后发布；cache不留Entity.text整文件或Entity.body。新窗口只为已打开的记录持有正文，按内容修订变化发送，不因每次计时心跳广播全部笔记。

合成数据验证建议：100/1000 条，正文 2KiB/64KiB，及现有 2000 条基线；这是测量样本，不是产品限制。比较当前代码与新代码的冷启动、一次计时提交、详情打开、内容保存、查找：read/list 调用、读取字节、耗时、heap 与目录增量。存储报告必须写实际结果，不能只写 UI 少显示了正文。

不加字数/条数上限，不截断详情和回执，不新建回执保留期。每次长详情写入回执仍保留完整输入，这份增长明确计入报告；历史已有8KB标记截断/60字显示摘要不另造限制。
