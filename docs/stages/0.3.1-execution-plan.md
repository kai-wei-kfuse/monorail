- 一个阶段一个或几个提交：`feat(g3): …` / `fix(g3): …` / `docs(g0): …`。每个提交前 `npm run check`。

## 2. 做法要点

### G1 兼容锁定
- 测试文件 `src/data/compat031.test.ts`：构造拆分后的两张卡（`today` 改了内容和时长、`rest` 的 `shrunk_from` 指向非 `已缩小` 卡）。`data/migrations/` 只冻结了 v1 读法，没有 0.3.0 的；从 tag `v0.3.0`（`23d6240`）拷 `cardSchema` / `stateSchema` / `settingsSchema` 和 `cardService.restoreInTx` 到测试夹具 `src/data/fixtures/v030/`，文件头注明来源提交、只读不改。用它们校验，并跑 0.3.0 的 `restoreInTx` 完成 `rest` 卡，断言不抛错、不改父卡（0.3.0 的 `restoreInTx` 只在父卡是 `已缩小` 时改父卡，见 `cardService.ts:22–27`）。
- 设置：带 `insertBackPlace` / `taskMode` 的 `settings.yaml` 用 0.3.0 的 schema 解析通过、写回仍带这两个键；缺这两个键时 0.3.1 解析得到默认值。
- 状态：插入中的 `state.yaml`（`resume_entry_id` 指向带 `card_id` 的普通条目）0.3.0 解析通过。
- 这一步先做：如果锁定失败，ADR 0021 第 4 / 8 条要改，后面的阶段不开工。

### G2 今日任务板
- `domain/plan/plan.ts`（纯函数）：`achieved(item, card, minutesToday)`、`minutesToday(entries, cardId, day, boundary)`（按活动日切，用已修好夏令时的 `splitAtDays`）、`candidates(plan, cards, tasks, entries, seen, runningId)`、`carry(yesterday, today, cards, minutesToday)`（未达成的项带过去、保留优先级、`today_minutes = min(昨天填的, 剩下的)`、标 `carried_from`；已定 49）、`dueOn(card, day)`（只标那天到期的，已定 16）。
- `planService`：`add / remove / edit / skip / confirmCarry`，都是 InTx + 根动作；卡被删除 / 放弃 / 冷藏时在同事务里移出板子（在 `backpackService` 对应 InTx 末尾调 `planService.dropCardInTx`，方向 backpack → plan，评审检查不反向）。
- 换日：`scheduler.onDayChanged` → `planService.rolloverInTx`：今天的文件不存在就建；有昨天未达成的项时把 `carried_confirmed: false`，首页 / 抽屉先问（已定 4：预先勾好，用户确认或去掉）；换日时还在计的卡自动带到今天并直接确认（已定 49 提议 6）。历史 `system.carry`，来源「系统」。
- 投影：新 `planProjection`（今天、明天两块板子的行：名字、MAIN/SIDE、优先级、今天已计 / 今天的量、达成、到期标红、是否正在计），每秒心跳只更新正在计那一行的数字。

### G3 抽卡
- `pick.ts` 新签名：`pick({ plan, cards, tasks, entries, day, seen, running, inserting, resting, random })` → `{ kind: 'task', card, candidates, resetRound } | { kind: 'plan' } | { kind: 'guide', guide }`。「今天先不排」时 `plan = null` 走整个背包的加权随机。`isCandidate` 保留。
- 现有 `pick.test.ts` 里阻塞、回顾卡、快到期、每日底线的用例删除，换成 ADR 0021 第 2 条的用例；`baseline` 还被底栏 `BaselineMarks`（0.2.5 已从界面去掉）、`homeProjection`、`homeSlice`、`entityChanges` 用着，pick 不再调它，其余用处开工时逐个核对，没人读了再删。
- `cardService.complete` 末尾的 `drawInTx` 去掉，改回 `home_mode = 'blank'`；`redraw` 不再调 `registerRefusalInTx`。

### G4 插入
- `services/insertPolicy.ts`（纯函数）：`insertDecision({ entry, resume, entrySource })` → `'insert' | 'switch' | 'replaceInsert' | 'start'`，表同计划第 10 节和 ADR 0021 第 3 条。所有入口（`startFreeInTx`、`startPresetInTx`、`continueEntryInTx`、`dispatchMiniCommand` 的新事件 / `startFavorite` / `continueEntry`、`startCard` 从抽屉）先问它。
- `endOriginalInTx`：同 ADR 0021 第 3 条；自由计时时只清 `resume_entry_id`、插入条目改 `普通`。历史 `home.endOriginal`，主体是原来那张卡。
- 插入中从抽屉开始另一张卡：`startCard` 内先 `endOriginalInTx` 再开始；结果一条历史（主体是新卡，连带改动里有原卡回待做）。
- MCP / CLI：`start_task_item` 在插入中同上处理，结果的 `reason` 写「先结束了原任务「…」」；`start_break` / `return_from_break` 映射到插入 / 回到任务，`allowed` 表（`applicationController.ts` 第 98–117 行）按新状态重算，测试同步。
- 小窗：`miniProjection` 加 `inserting: { originalTitle, todayMinutes, todayGoal } | null`，小窗显示〔↩ 回到 …〕（同 0.3.0 的〔回来〕位置），点了发 `resume` 命令（已有）。

### G5 缩小、接着做、降级
- `splitCard`：ADR 0021 第 4 条；`cardService.split(ctx, cardId, { todayContent, restContent, todayMinutes? }, at)`：改 `today`、建 `rest`、改板子上的 `today_minutes`，一个事务；历史 `card.split`（改前值有原内容和原时长）。旧的 `shrink` 入口删除（MCP / CLI 没有暴露缩小，`shared/application.ts`、`cli/`、`mcp/` 里 grep 不到 shrink，已核对）。
- 「从哪一项缩小来的」只给鼠标提示：从操作历史读这一条的改前内容，读不到不显示（ADR 0021 第 4 条）。
- 接着做：`complete(..., keepGoing=true)` 改成 `keepGoingInTx`：写 `progress_note`、`releaseCard`、停计时，不 `continueCard`；历史动作仍是 `card.complete` 还是新 `card.keepGoing`——用新的，回看和历史显示「接着做」更清楚。
- 降级：`registerRefusalInTx` 的两处调用删掉（`shrink`、`redraw`）；`degradeService` 里 `returnFromRest` 保留只给启动时的一次性处理；`restInTx` 新增在 `homeService`（插入一条「休息」，项目「休息」）。`RestCard` 不再渲染（`home_mode: 'rest'` 只在 0.3.0 数据里出现，启动处理后清掉）。
- 阻塞：快速记录条〔阻塞〕、编辑事项开关、背包 BLOCK 标记删除；记录和卡文件照写 `blocking: false`；`capture_todo` 的 `blocking` 参数和 CLI `--blocking` 照收、描述改成「0.3.1 起不起作用，保留只为兼容旧调用」。

### G6 设置
- `shared/settings.ts` 加 `insertBackPlace`（enum `bottom/top`，默认 `bottom`）、`taskMode`（boolean，默认 `true`）；`schemas.ts` 对这两个键加 `.default()`（照 `miniMode`）。
- 设置页 `sections.ts`：02 去掉 `shrinkMaxLevel` 和拒绝五项、加任务模式；05 预设编辑器去掉 `mode`（文件照写）；06 加回去区域位置。`settings.test.ts` 同步。
- `CLAUDE.md`「settings.yaml 是当前配置来源」那一条补：「新加的键可在 schema 里给 default（ADR 0021 第 8 条）」。

### G7 界面
- 首页：`InsertCard`（叠卡 + 回去区域 + 红色烟雾 + 确认框 + 动画，参数取 §11.14，写成 `pages/home/insert.css` 的变量，动效等级读 `motion` 设置）；`AwayDrawer` 删除；`FusedCard` / 分开布局的 `TaskCard` 去掉〔再抽一张〕、加〔休息一下〕；待机时〔今日任务板〕；`ShrinkDialog` 换成拆分对话框。
- 抽屉：放 `pages/home/drawer/`（抽屉是首页的一部分，页面之间不能互相引用，所以背包的组件从 `pages/backpack/` 挪进来；想法池组件 `IdeaPool` 同挪，`pages/backpack/` 删除）。`BagDrawer`、`TodayBoard`、`QuestCard`（便签）、`QuestDetail`、`PlanPopover`、`NewQuestDialog`、`FlipDeal`。抽屉开合、Esc、点上面卡收起、点〔开始〕后收起。
- 顶栏去掉「背包」，`ui/frame` 和路由同步；快捷键或托盘里打开背包的入口改成打开抽屉。
- gallery：`gallery.html?page=live` 加抽屉、插入卡、翻卡、缩小各状态，无头截图和原型截图对照（§11.14 / §11.15 列的截图编号）。
- 窄窗口：960×600 下抽屉、今日任务板 380px 放得下（原型 `size=960x600` 截图 08、17 为准）。

### G8 附带需求
- `update_time_entry`：输入 `{ operation_id, expected_state, entry_id, start?, end?, description?, project?, tags? }`；走 `timeEditService.update / patch`（日历同一套规则：覆盖确认、跨日、正在计的条目只能改开始）；结果同 `add_time_entry` 的 `overlaps`；历史 `auto.update_time_entry`。方法数 16 → 17，写方法 11 → 12：同步 MCP 工具表、CLI `entry edit <id>`、`docs/application/README.md`、`mcp/README.md`、设置 09 能力列表与它的测试。

## 4. 风险

| # | 风险 | 处理 |
|---|---|---|
| R1 | 拆分后的卡被 0.3.0 读坏（`shrunk_from` 指向非 `已缩小` 卡） | G1 先写锁定测试；失败就改 ADR 第 4 条（例如 `rest` 不写 `shrunk_from`，来历只靠历史） |
| R2 | 新设置键缺省用 default 违背 `CLAUDE.md` | 按 `miniMode` 先例，ADR 第 8 条写明并改 `CLAUDE.md`；审核可否决改成「首次启动补写」 |
| R3 | 所有入口改插入后漏了某个入口（例如快速记录条、MCP `start_timer`） | `insertDecision` 单一入口 + 测试里枚举所有调用 `startInTx` 的地方（grep 断言） |

| R5 | 板子「今天已计」每秒重算拖慢心跳 | 投影只在提交后重算整块，心跳只加正在计那一行；`history.perf.test.ts` 同类加一个 50 项板子的用例 |
| R6 | 背包页并进首页抽屉，页面之间不能互相引用 | G7 把组件挪进 `pages/home/drawer/`，eslint 分层检查兜底 |
| R7 | 删除阻塞、回顾卡、降级计数后，0.3.0 退回时这些机制重新出现 | 用户已接受（已定 17）；发版说明写明 |
| R8 | `get_context.today_plan`、`start_task_item` 行为变化影响已配好的 agent | 只加输出字段；行为变化写进 `docs/application/README.md` 和发版说明 |

## 5. 交给审核的要点

1. ADR 0021 第 1 条 `plans/` 的存法和「派生不存」的划分是否够用、有没有漏掉要存的东西（例如「今天先不排」是否该放 `state.yaml`）。
2. 第 3 条插入扩大到所有入口后，`resume_entry_id` 这一个字段是否够表达「插入中再换一件事」「插入的事停了还在等」两种状态（0.2.5 原机制只有前者）。
3. 第 4 条拆分时原卡 id 不变、改内容的做法，对回看「完成的卡」、操作历史、MCP `find_items` 是否有副作用。
4. 第 6 条删掉降级计数后，`state.yaml` 里继续写的旧字段、`RestCard` 的去留是否干净。
5. 第 8、9 条两个新设置键用 schema default，是否接受；或者要求改成别的做法。
6. 阶段划分、依赖和分线是否合理；G1 放第一是否必要。
7. 有没有计划已定 0–55 里没有落到本方案或 ADR 的条目。
