# 0.3.1 开发执行方案（任务卡 RPG 化）

版本 v1.1 · 2026-11-06 · 状态：第 1 轮审核（pro-b-4，`evidence/0.3.1-plan-review-round1.md`）意见已全部处理，待复核；另有 1 条要用户定（插入的事要不要能暂停，见计划 v0.29 待确认第 1 条）。需求来源 [0.3.1 计划](0.3.1.md) v0.29（已定 0–55）与 [流程图](0.3.1-flows.md) v0.10；数据与规则见 [ADR 0021](../adr/0021-today-plan-insert-split.md) 修订 2；界面见 `../UI风格规范.md` §11.14、§11.15 和两个原型。路径相对 `app/`。版本 `0.3.1-beta.1`（D0 已同步）。

## 0. 不变量

- `CLAUDE.md` 的分层、事务方向、`schemaVersion: 2` 不变；不写迁移。
- 退回 0.3.0 不坏数据：卡、记录、任务、状态文件**不加 0.3.0 会拒绝的字段或枚举值**（卡上只加一个可选的 `split_note`，`passthrough` 原样保留；状态文件一个字段都不加，因为 0.3.0 会丢掉未知字段）；新数据进 `plans/`；设置新键标 `defaultWhenMissing`；历史 change type 不加枚举值（ADR 0021 第 8 条表）。
- 只暂存本方案负责的路径；`evidence/journal-real.json` 不提交、不回退；`src/app/recapBoard.test.ts` 现有未提交改动不是本方案的，不碰。
- 不覆盖日常安装版；真窗口一律用隔离身份；未实测写「未测」。
- 一个阶段一个或几个提交：`feat(g3): …` 等。每个提交前 `npm run check`。

## 2. 做法要点

### G1 兼容锁定
- 冻结：把当前 `schemas.ts` 里的 `cardSchema / recordSchema / taskSchema / settingsSchema`、`stateRepo.ts` 里的 `stateSchema`、`historyRepo.ts` 的记录 schema 拷到 `src/data/migrations/v030/`（文件头注明来源 tag `v0.3.0`、提交 `23d6240`，以后不改），同 `migrations/v1/` 的做法。当前 `src/` 与 tag `v0.3.0` 相同（`git diff --stat v0.3.0 HEAD -- src mcp cli` 为空），所以拷当前文件即可。
- 测试 `src/data/migrations/v030/compat.test.ts`：
  1. 拆分后的 `today`（改了内容和时长）、`rest`（`shrunk_from` 指向非 `已缩小` 卡、带 `split_note`）过 0.3.0 `cardSchema`，`split_note` 在解析结果里保留；照抄 0.3.0 `restoreInTx` 的判断（`cardService.ts:22-27`）完成 `rest`，父卡不变。
  2. 「待机 / 插入」条目 + `resume_entry_id` 指向带 `card_id` 的普通条目，过 0.3.0 的 `entrySchema` 和 `stateSchema`，`assertEntries` 不抛。
  3. 带 `insertBackPlace` / `taskMode` 的设置文件过 0.3.0 `settingsSchema`、写回仍带这两个键。
  4. 板子改动记成 `type: card / state` 的历史记录过 0.3.0 历史 schema。
- 锁定失败就先改 ADR 0021，后面不开工。

### G2 今日任务板数据与换日
- **`CLAUDE.md` 方向表先补**（公共文件，交接里说明）：`dealService` 读 `planService`（只读）；`homeService` / `cardService` 调 `planService` 的 InTx（开始卡时清 `skip_until_planned`、缩小改量、接着做不动）；`newDay()` 调 `planService.rolloverInTx`；`planService` 只依赖 domain 和 tracking/api 的只读查询（今天已计），不调别的 service。卡离开背包不写板子（ADR 第 1 条派生过滤），所以没有 `backpack / review → plan`。
- `domain/plan/plan.ts`（纯函数）：`minutesToday(entries, cardId, day, boundary, at)`（按活动日切，用已修好夏令时的 `splitAtDays`）、`achieved(item, card, minutesToday)`、`visibleItems(plan, cards, tasks)`、`candidates(...)`、`carryFrom(source, today, cards, tasks, minutesToday, running)`、`dueOn(card, day)`（只标那天到期，已定 16）。
- `planService`：`add / remove / edit / skipToday / skipCard / confirmCarry`（根动作 + InTx）；`rolloverInTx`；`dropMissingInTx` 不做（派生过滤）。
- `newDay()`（`bootstrap.ts:84-89`）：`expireInTx` → 0.3.0 `state.rest` 一次性处理 → `rolloverInTx` → `refreshInTx`。启动和 `scheduler` 换日都走这里。
- `planProjection`：今天、明天两块板子的行（MAIN/SIDE、名字、优先级、今天已计 / 今天的量、达成、到期标红、正在计、带过来待确认）；提交后整块重算，心跳只更新正在计那一行（R5）。
- 历史：`shared/history.ts` 登记 ADR 第 11 条的动作；`historyCapture` 加 `plans` 前后比较，输出 `card` / `state` 类型的改动。
- 保留期：`historyService.maintain` 的清理加 `plans/`，同 180 天。

### G3 抽卡
- `domain/picker/pick.ts`：`pickFromPlan({ plan, cards, tasks, entries, day, boundary, at, insert, legacyRest, random })` → `{ kind: 'task', card, candidates } | { kind: 'plan' } | { kind: 'confirmCarry' } | { kind: 'blocked', reason } | { kind: 'done' }`；「今天先不排」时候选是整个背包。旧 `pick` 删除，`pick.test.ts` 旧用例删除，按 ADR 第 2 条重写。
- `dealService.drawFromPlan(ctx)`：`readSerial` 只读排队，返回结果；没有写盘、没有历史。`drawInTx` / `refreshInTx` 里写 `current_card` / `home_mode: 'task' | 'review' | 'guide'` 的部分删除，`refreshInTx` 只保留「当前卡不再是待做 / 进行中就清空」和旧 `home_mode` 归一到 `blank`。
- `cardService.complete` 末尾不再 `drawInTx`；`redraw` 删除（〔换一张〕是 `planService.skipCard`）；`skipCard` / `skip_count` 不再写。
- `get_context.today_plan`：`shared/application.ts` 加输出字段；`mcp/compatibility.test.ts` 加旧 SDK 读取用例。

### G4 插入
- `domain/timeline/insert.ts`：`insertState(open, resumeEntry)` → `'inserting' | 'waiting' | null`；`entryAction(state, open, source)` → `'insert' | 'replace' | 'switch' | 'start'`，source 取 `quick | temp | favorite | timerBox | mini | recent | continue | mcpTimer | mcpBreak`，表同 ADR 第 3 条。表驱动单测每个 source 一行。
- 改动的 InTx（判断放内部）：`startFreeInTx`、`startPresetInTx`（看 `place`）、`continueEntryInTx`、`dispatchMiniCommand` 的 `editOpen` 新事件、MCP `start_break` 找预设的条件、`startTimerCheckedInTx`。
- tracking：`timerService.stopInTx` 在插入状态下改成开 `待机 / 插入`、不清 `resume_entry_id`；新增 `promoteInsertInTx` 并从 `tracking/api.ts` 导出。
- `homeService.endOriginalInTx`、根动作 `endOriginal`；`restInTx` 见 G5。
- 插入中禁止开始另一张卡：`startCardInTx` 开头检查 `insertState`，非 null 抛 `IN_AWAY_ACTIVITY`；界面据投影灰掉按钮。
- MCP / CLI：`checkNormalPreconditions` 对 `start_timer` 放行插入状态；`allowed` 表（`applicationController.ts:94-118`）`away` 加 `start_timer`、`stop_timer`，第 243 行提示改写；`pause_timer` 在插入中报 `PAUSE_NOT_SUPPORTED_IN_BREAK`（新错误码，写进 `docs/application/README.md`）；`start_task_item` 在插入中照旧 `IN_AWAY_ACTIVITY`。
- 删除 `cardService.leaveTo`。
- R3：测试里 grep 所有调用 `startInTx` 的地方，断言都经过 `entryAction` 或在白名单里（系统待机、休息、睡眠、离线）。

### G5 缩小、接着做、降级、新建任务、提醒
- `domain/card/shrink.ts` → `splitCard`；`cardService.split(ctx, cardId, { todayContent, restContent, restMinutes? }, at)`：一个事务改 `today`（经 `editContentInTx`）、建 `rest`（带 `split_note`）、改板子上的 `today_minutes`。历史 `card.split`。
- 接着做：`cardService.keepGoingInTx`，历史 `card.keepGoing`；`complete` 去掉 `keepGoing` 参数。
- 降级：删除 `registerRefusalInTx` 的调用和 `degradeService` 里只剩启动一次性处理需要的部分；`homeService.restInTx` / `rest` 根动作（插入一条「休息」，历史 `home.rest`）。
- 阻塞：快速记录条〔阻塞〕、编辑事项开关、背包 BLOCK 标记删除；文件照写 `blocking: false`；`capture_todo.blocking` 与 CLI `--blocking` 照收、描述写「0.3.1 起不起作用」。
- 新建任务（已定 46）：`shared/backpack.ts` 的 `TaskDraft.items` 改成 `{ content, type, minutes }[]`（旧调用传 `string[]` 时按结果卡兼容一个版本）；`backpackService.createTaskInTx` 按类型建卡。
- 时间盒今天计够只提醒（已定 49 提议 3）：`domain/reminders.ts` 的 `planReminders` 加一类 `todayGoal:<cardId>:<day>:<today_minutes>`，时间 = 开始时刻 + (今天的量 − 今天已计)；通知文字「「名字」今天的 N 分钟到了」，不停计时。

### G7 界面

  - 插入卡 `pages/home/InsertCard.tsx` + `insert.css`（§11.14 的数值写成变量，动效等级读 `motion`）。按钮排只有〔停止〕（等用户定插入暂停）。「停了还在等」显示「已停 · 还在等你回去」。

  - **大读数显示今天在这张卡上的时间，总累计挪到标题下小字**（已定 23）：`homeProjection` 输出 `todayElapsed` 和 `totalElapsed`，`FusedCard` / 分开布局 `TaskCard` 改读数来源。
