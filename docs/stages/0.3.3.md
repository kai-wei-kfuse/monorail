### 技术完整性与兼容不退化（不需用户另批）

- 改标题不得覆盖已有详情。旧数据不能假定 body 为空。不静默截断或丢掉未提交内容。
- 未提交详情是第二份草稿：只写详情也必须挡住安装更新；收起或切待办后草稿还在也算脏。新建 body 用详情或空串，不镜像标题；已有记录省略详情则保持原文。
- 旧多行 `text` 后半截查找默认仍要能匹配：这是兼容不退化，不是用户新要求，也不是「要不要保留」的待定项。新的正文搜索语义由执行方案定。
- 想法笔记大窗口的未提交详情也必须算脏（关闭与安装更新）；主窗重载后旧窗保存须拒绝。主窗是业务写入者。不另开平行写入、不给新窗 fs 写权限、不复用 `save_quick_record`。有未保存草稿的视图只聚焦、不按主窗修订重载盖掉；保存成功后同记录各视图收到新修订，还脏着的只提示冲突、不强制替换。从编辑态打开新窗时，原视图必须保留草稿/dirty，不能把草稿误广播成已保存。这是完整性约束，不需用户另批。
