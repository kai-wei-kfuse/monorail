- 新领域task/complete.ts仅维护Task元数据、快照/成员校验与核验ID，不导入card/transitions。`domain/card/transitions.ts` 新增/扩展共享纯转换 `completeCardItem(card, at, day, track, note?)`（允许 `待做 | 进行中`，`note === undefined` 时保留已有 `progress_note`）与 `reopenCardItem(card)`（要求 `已完成`，恢复 `status = '待做'` 并清 `completed_at/day/track`，保留 `progress_note/order/project/tags`），由 `cardService` 与 `backpackService` 组合共用。
- 冻结0.3.1相关task/card schema及MdRepo.write路径（注明tag/hash）。验收分别报告：①旧schema.parse新对象；②旧版read→改已知字段→write后嵌套completion.cards[].before及completed_at仍在；③旧版改成员/批次后新版拒绝撤销且不覆盖。0.3.0/0.2.5按相同分类复查，parse不代表写回或EXE实测。

### P2：共享事务与投影（v1.7，吸收S1/S2/S4/S5）

- **唯一服务编排归属（防反向边，S1）**：`completeTaskItemInTx` 归属 **`cardService`**（直接复用 `restoreInTx`、`finishItemInTx`、`alignInTx`）；`completeTaskInTx / reopenTaskInTx / reopenTaskItemInTx` 归属 **`backpackService`**（直接复用 `makeRoomInTx`、`putInBackpack`）；两者仅共用 `domain` 纯转换与 `tracking/api`，`cardService` 与 `backpackService` 不互相导入或调用根动作。所有校验在提交前，快照/卡/状态/history/receipt原子。
- **单子项完成（`cardService.completeTaskItemInTx`，S4/S5）**：严格按实体存在→冷藏/已放弃父任务拒绝（`TASK_NOT_ACTIVE`）→`已完成` 子项立即幂等 `noop`（即使父支线刚因该尾项完成而自动完成，新 `operation_id` 重调仍返回 `noop` 且不重写日期）→父任务 `inBackpack` 校验→`待做|进行中` 校验。若该卡不是当前首页卡且非插入等待原卡，直接标为 `已完成`，不强制 `requireCurrent`，不触碰当前正在运行的其他卡/自由计时/插入事件；若该卡正是当前首页卡（含运行中与**卡自身暂停** `open?.kind === '暂停'`）或插入原卡，校验 `insertStateInTx`（拒绝 `IN_AWAY_ACTIVITY`）、真实待确认字段 `Boolean(tx.state.pending_id || tx.state.pending_at)`（拒绝 `PENDING_START_CONFIRMATION`）与时间盒提前完成确认（运行或卡暂停未达量均须 `finishEarly=true`，GUI 与 API 口径一致），停该卡计时并清 `current_card/home_mode`。随后调 `afterItem(task, tx.cards, tx.at)`（支线最后一项完成后自动完成，主线保持在背包进行中）。
- **单子项取消完成（`backpackService.reopenTaskItemInTx`，S2/S4/S5）**：严格按实体存在→父任务冷藏/已放弃拒绝（`TASK_NOT_REOPENABLE`，绝不自动恢复或藏入冷藏任务）→`待做` 子项 `noop`（若同时传了 `makeRoom` 则拒绝 `MAKE_ROOM_NOT_NEEDED` 防误腾位）→`已完成` 子项校验。父任务在背包进行中时若传 `makeRoom` 拒绝 `MAKE_ROOM_NOT_NEEDED`，主线先校验主线剩余活跃名额 `itemCapacity(task, tx.cards, limits) <= 0`（第三参 `PoolLimits` 取动态 `tx.settings.mainItems` 而非固定5；剩余名额 `<= 0` 时拒绝 `MAIN_TASK_ITEMS_FULL`），再将目标卡恢复为 `待做`（不重开计时）；若父任务已处于 `已完成`，同一事务内先校验 `itemCapacity(task, tx.cards, limits) <= 0`，再恢复父任务回原槽位（满格无 `makeRoom` 报 `TASK_CAPACITY_FULL`；`makeRoom` 对象同样执行局部计时保护 S2：含插入原卡报 `IN_AWAY_ACTIVITY`、含 `pending_id/pending_at` 关联卡报 `PENDING_START_CONFIRMATION`；保留原 `bet_ends_at`，清空 `completed_at/completion` 防止失效批量快照残留），且仅将该目标子项恢复为 `待做`。
- 完成整张任务不调leaveBackpack（会清bet_ends_at）。先在任务仍进行中时取track=task.slot，批量写剩余活跃卡completed_track后，最后写Task完成与slot_index=null；保留slot和bet_ends_at。若主线全部子项此前已逐个完成，`completion.cards` 为 `[]`，整张重开后主线回背包且各子项保持完成。测试主线本批卡轨道仍是主线、笔记不变、格号已空、押注日期仍在。
- 统一自动afterItem完成时间、slot_index=null、completion=null；复核cardService、backpackService中全部afterItem调用。新自动完成不遗留旧手动快照。
- 既有restoreTask遇已完成走新共用路径；其他冷藏/放弃不改行为。`reopenTaskInTx` 在目标任务已处于背包进行中时，若传 `makeRoom` 拒绝 `MAKE_ROOM_NOT_NEEDED`，未传返回 `noop`；`makeRoomInTx` 统一执行 S2 局部计时保护。恢复复用putInBackpack的格位校验/分配后，明确把结果bet_ends_at覆盖回Task原日期再保存，不直接持久化它新生成的周期。测试原11月20日截止在重新打开后不变；旧任务null保持null。
- doneSides替换为结构化doneTasks，覆盖主线、支线、旧自动完成；UI和自动化都读共享投影/领域状态。
- 登记手动/自动化history action（含 `card.reopen` 与 `auto.reopen_task_item`），TASK白名单只加完成时间，不加入completion快照，避免整包JSON进历史。

## 4. 风险与检查点

| 风险 | 必须检查 |
|---|---|
| 撤销覆盖原有完成或旧版后续修改 | 字段差量快照、成员/完成批次校验、全有或全无 |
| 子项取消完成突破主线容量或使已完成父任务悬空 | 主线校验 `itemCapacity(task, tx.cards, tx.settings) <= 0`（动态 `mainItems`）；父任务已完成时同事务恢复父任务、支持 `makeRoom`（局部保护插入/pending）并清旧 `completion` |
| 再打开会启动计时/丢其他任务 | 进行中→待做、不重开timer；只停完成目标引用 |
| 任务恢复满格自动破坏他项 | 明确makeRoom，取消不写，选中对象同事务校验 |
| completion通过旧版后过期 | 状态派生与提交校验，不加跨状态refine封死合法目录 |
| readonly嵌套队列死锁/被当写请求 | 服务读InSerial路径、Rust分类与四层实调 |
| expected_state被误当全局版本 | timer token只负责计时；day与completion_id保护各自语义 |
| 分组统计另算/响应被静默截断 | 复用现有计算，完整明细，无未经证明的新cap |
| 文档/代码/新旧客户端不一致 | 36方法矩阵、旧17回归、strict输出、帮助/设置/README同步 |
| 未提交草稿提前写pending、失焦记账或跨窗复活 | 唯一owner、零写begin/cancel、viewSeq、目标令牌、生命周期实测 |
| 擦除动画推迟计时或打断时重复开始 | 点击at、成功后单次呈现、回调只改展示、失败/打断矩阵 |
