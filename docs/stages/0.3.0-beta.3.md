### 1.3 保留 `F5` 刷新并修复主窗口重载后小窗口假报「主窗口未响应」（已记录，待统一开发）
1. **问题根因**：
   - 用户确认保留 `F5` 直接刷新页面的能力（同时「设置 → 更换数据目录」也会调用 `window.location.reload()` 重载主窗口）。
   - 主窗口重载后，新的 `Ctx` 事务版本号 `revision` 从 `0` 重新计数（启动后通常为 `2`）；而未销毁的小窗口在 `src/platform/windowBus.ts` 的 `miniWindowBus.onSnapshot` 中仍保留着刷新前更高的 `revision`（例如 `10`），因 `if (event.payload.revision < revision) return;` 将主窗口发来的新快照与每秒心跳全部丢弃，直到主窗口新 `revision` 追平旧值前一直显示「主窗口未响应」。
2. **修复要求**：
   - 在主窗口小窗快照链路（`MiniSnapshot` / `connectMini` / `windowBus.ts`）中引入主窗口会话标识（或会话世代令牌）：同一主窗口会话内继续拦截乱序旧 `revision`；当主窗口按 `F5` 刷新或更换数据目录重载产生新会话时，小窗口识别到新会话立即重置本地 `revision` 基准并接纳新快照（同时清理挂起在旧会话上的编辑态），不再误报「主窗口未响应」。

### 1.4 修复小窗口与 mini 窗口黑色计时区切角瑕疵（方案 A，已记录，待统一开发）
1. **问题根因**：
   - `src/app/shell/shell.css` 中 `.mini-r`（`clip-path: polygon(16px 0, 100% 0, 100% calc(100% - 14px), calc(100% - 14px) 100%, 0 100%, 0 16px)`）与 `.miniwin.tiny .mini-r`（`10px` 切角）把右下角切掉后，在真实 Windows 窗口中露出了底层 `.miniwin` 的浅白背景（`var(--paper)`），导致黑色计时块右下角出现突兀的白色小三角。
   - 同时 `.mini-r` 左上角斜切露出的浅白三角区域超出了左侧 `.mini-l` 的宽度范围，而 `1px` 灰色上边框（`inset 0 1px 0 var(--line-2)`）仅画在 `.mini-l` 上，导致左上斜切顶端出现一段无边框的断线缺口。
2. **修复要求（用户确认采用方案 A）**：
   - 保留 `.mini-r` 左上角的斜切过渡（普通小窗 `16px`、mini 窗口 `10px`），去掉右下角切角（改为 `100% 100%`），使黑色计时块完整填满窗口右端与右下角；
   - 将外层 `.miniwin` 的上下 `1px` 内边框（`inset 0 1px 0 var(--line-2), inset 0 -1px 0 var(--line-2)`）延伸覆盖至斜切露白区域，确保左上斜切处的顶边线条连续不断裂（普通小窗与 mini 窗口同步生效）。

### 1.5 移除「快捷活动」弹层中硬编码预置的系统「睡觉」磁贴（已记录，待统一开发）
1. **问题根因**：

2. **修复要求**：
   - 从 `src/app/shell/QuickActs.tsx` 中移除硬编码的「睡觉」磁贴（及不再使用的 `onSleep` 属性接线），使「快捷活动」弹层仅渲染用户在设置中配置的快捷活动列表（`acts`）与底部临时活动输入行，并同步更新 `src/app/shell/quickActs.test.ts`。

### 1.6 重构「回看（Recap）」多维度图表与二级折叠明细列表（已确认方案，待统一开发）
1. **现状问题**：
   - 现有 `Recap.tsx` 仅在待办每周回顾的第 `01` 步可见（完成回顾后「回顾」页只显示空白完成提示，平时无法查看统计）；
   - 仅有按项目分类（`project`）的单一维度，且条形图全部为纯黑虚线，无项目/标签颜色区分；
   - 将「待机」与「睡眠」混入总时长计算，缺少占比百分比、每日趋势柱状图以及分组下具体做了哪些事的列表明细。
2. **用户确认的完整设计方案**：
   - **入口与周期切换（随时可看 + 7 种周期下拉选择）**：
     - 在「回顾」页中，即使本周回顾已完成（或尚未到回顾日），也始终开放「回看」统计视图（当存在未完成的每周回顾流程时，作为第 `01 回看` 步骤展示；当本期回顾已完成时，直接展示回看看板并在顶部提示本期回顾已完成）。
     - **控制栏 UI 精简为下拉选择框（不平铺按钮）**：`PERIOD 周期` 与 `GROUP BY 分组` 均采用任务卡同款带右侧黑底箭头块（展开变强调色）的精简下拉框（保留中英文标签对照），避免一排平铺分段按钮占用过多横向空间。
     - **支持 7 种统计时间范围**：**「本周（THIS WEEK）」**、**「上周（LAST WEEK）」**、**「本次回顾周期（SINCE LAST REVIEW）」**、**「本月（THIS MONTH）」**、**「近 3 个月（LAST 3 MONTHS）」**、**「最近一年（LAST 1 YEAR）」**、**「自定义时间（CUSTOM RANGE，选定后紧跟起止日期选择器）」**，并提供「含待机/睡眠」开关（默认关闭，仅统计有效活动时长）。
   - **自定义时间选择器（v1.9）**：不用系统原生日期控件。触发按钮沿用下拉框造型，显示 `2026.10.20 – 2026.11.04`，右端黑块为日历图标；弹层为黑色细边框 + 顶部黑条强调色短条，上方「FROM 开始 / TO 结束」两格与「共 N 天」，中间并排两个月（固定 6 行、左右翻月），起止日黑底强调色数字加底部 3px 强调色条，区间铺 22% 强调色，今天 1px 黑框，早于最早记录或晚于今天不可选；先点开始、再点结束（顺序不限），选结束前悬停预览区间；〔确定〕或回车生效，〔取消〕、Esc、点外部放弃；周期下拉选「自定义时间」时直接弹出。
   - **顶部核心概览卡片（KPI Cards）**：
     - **有效投入总时长**（`HH:MM` + 日均有效时长）。v1.16 用户确定按**实际占用时间**计：去掉待机 / 睡眠后，同一时刻有几条记录并行也只算一次；各分组把并行时段按同时进行的条数平均分摊，使分组合计等于有效投入、占比合计 100%。
     - **主线投入（v1.9 取代「首要投入」）**：主线占有效时长的百分比，下方「主线 / 支线 / 自由 / 临时离开」分段小条，及主线、支线时长
     - **完成的事项卡**（数量及主线/支线分布）
     - **进度笔记（「做到哪了」）与记录条数**
     - **与上一期对比（v1.9）**：四张卡底部统一一行「较上周 ▲ 01:55 / ▲ 2 张 / ▼ 2.1 个百分点」，贴底对齐。上一期为紧接本期之前的同样天数；「本月」对比上月同期；上一期早于最早记录时显示「较前一年 —」不对比。增减只用 ▲（黑）/ ▼（灰），不用红绿。
   - **4 种分组索引维度（下拉框切换，保留英文小字）与色彩映射**：
     1. **按分类（`PROJECT`）**：直接复用 `settings.lists.projects` 中各项目配置的 `color`（未配置或系统项配固定辨识色）。
     2. **按标签（`#TAG`）**：统计各 `#标签` 投入时长（无标签归入「无标签」），采用高对比度工业色板区分。
     3. **按任务来源（`TASK & SOURCE`）**：按 **主线任务（关联主线卡）**、**支线任务（关联支线卡/游离卡）**、**自由活动（无关联卡普通计时）**、**临时离开（`kind === '插入'`）** 四类聚合。
     4. **按具体活动（`ACTIVITY`）**：按条目描述 `description` 聚合同名活动，直观展示最耗时的 Top 活动排行。
   - **双图表可视化区（Charts）**：
     1. **左侧/主图：自适应粒度分色堆叠柱状图（`<=16 天`按日 `DAILY TREND`、`17~100 天`按周 `WEEKLY TREND`、`>100 天`按月 `MONTHLY TREND`）**：每根柱子按当前选中的索引维度分色堆叠；悬停显示该天/周/月总时长与各分项明细，点击某根柱子可高亮并过滤下方列表。
     2. **右侧/副图：整体构成环形图（SVG Donut）+ 分段构成条**：中心显示总时长，外环按当前维度分色展示各分项占比（`%`），右侧配 Top 图例。
   - **下方二级折叠分组明细列表（Hierarchical List）**：
     - **一级汇总行**：`[■ 颜色块]  分组名称（分类/标签/来源/活动）  [条数徽标 N]  [同色水平占比条]  占比 XX.X%  累计时长 HH:MM`。
     - **二级展开行**：点击一级行展开该组下合并后的具体活动与单条时间明细（显示活动描述、所属项目/标签/任务卡标记、日期与起止时间、时长），并与下方的「完成的卡」和「做到哪了」笔记区块协同展示。
     - **增减列（v1.9）**：查看整个周期时，一级行在占比与时长之间显示较上一期的增减（`▲ 00:50` / `▼ 00:20`），上一期没有的组标「新出现」，列表下方注明对比区间及上一期有、本期没有的组；按柱子筛选某天/周/月时隐藏该列。
   - **「完成的卡」与「做到哪了」（v1.9）**：
     - 两区标题右侧各有〔列表 | 卡片〕分段切换，两区共用一个状态，默认卡片；按日期从新到旧。
     - 卡片模式沿用背包任务卡牌（`.qc`）只读紧凑版：左侧竖条主线黑 / 支线深灰，竖排 `MAIN`/`SIDE`（笔记为 `NOTE`）与强调色「主 / 支」，主线卡黑框顶部 3px 强调色，右下 14px 折角。完成的卡：`MAIN/SIDE QUEST` + 日期、内容（重点词强调色底块）、所属任务、虚线下 `DONE ✓` 与「用时 HH:MM」；做到哪了：`PROGRESS` + 日期、左侧细线的笔记原文、「主线/支线 · 任务」。

   - **记住上次的选择（v1.16 用户确定）**：周期（自定义时记具体日期）、分组、含待机 / 睡眠开关、列表 / 卡片模式下次打开时恢复；存在这台电脑的应用配置里，不写 `settings.yaml`，不产生操作历史（执行方案 E7）。

### 1.7 新增「操作历史记录（Operation History）」功能（已确认方案，待统一开发）
1. **背景与安全边界说明**：
   - 单轨的共享应用接口（MCP / CLI 共 15 项方法）在设计上未开放任何删除计时条目、删除卡片/任务或清空数据的接口（且 `add_time_entry` 仅并行追加不覆盖）；但用户需要清楚掌握「CLI / MCP 究竟执行了什么操作」以及「自己手动执行了哪些增删改操作」。
   - 目前 MCP / CLI 的每次写操作已通过同一 journal 事务在 `receipts/<operation_id>.json` 中持久化了 `command`、`input`、`data` 与 `committed_at`，但尚无界面展示，且桌面端手动操作尚未记录可读审计摘要。
2. **用户确认的完整设计方案**：
   - **入口与联动**：
     1. **主入口（顶栏「列表 LIST」页）**：在「列表」页顶部工具区增加分段切换 **`[ 计时记录 | 操作历史 ]`**，方便日常随时查阅。
     2. **快捷预览入口（「设置 → 09 AI 与自动化」）**：在「AI 与自动化」说明页展示最近 N 条 AI / 自动化调用记录摘要，并提供「查看全部操作历史」按钮一键跳转至「列表 → 操作历史」（自动选中「仅 AI」筛选）。
   - **记录范围与来源分类**：
     - **AI / 自动化操作（`source: 'ai'`，可细分 `mcp` / `cli` 或外部应用接口）**：涵盖全部 10 项写方法（`save_idea`、`capture_todo`、`start_timer`、`start_task_item`、`pause_timer`、`resume_timer`、`stop_timer`、`start_break`、`return_from_break`、`add_time_entry`），关联 `operation_id`。
     - **桌面端手动关键操作（`source: 'manual'`，含主窗口、小窗、快速记录条）**：涵盖用户显式触发的写事务（开始/暂停/恢复/停止计时、插入临时活动/回来、手动补录、日历/列表新建/修改/移动/复制/删除计时条目、快速记录/保存想法/捕获待办、完成/缩小/放弃/PASS/新建事项卡与任务、修改设置等）；**排除**后台每分钟自动日界检查或启动空对账等无实质变更的内部事务。
   - **展示内容与交互**：
     - **筛选器**：支持按来源 **`[ 全部 | 仅 AI 与自动化 | 仅手动操作 ]`** 分段筛选，并支持关键词搜索（匹配动作名称、活动/卡片内容或 `operation_id`）。
     - **按天分组时间线**：与列表页一致按天分组，每行显示：`时刻（HH:mm:ss）` + `来源徽标（[AI · MCP/CLI] 强调色黑底徽标 / [手动] 浅灰徽标）` + `动作类别（如：保存想法 / 开始计时 / 删除计时条目 / 完成卡片）` + `可读内容摘要（如：「撰写技术方案」（工作 · 15:00–15:30））`。
     - **详情展开（可选）**：点击某条记录可展开查看详细字段（如修改前后的时间/描述对比，或 AI 调用的 `operation_id` 与原始参数）。
3. **v1.11 用户确认的记录规则与原型（2026-11-04）**：
   - **记录口径**：只要改动了数据就记，手动与 MCP / CLI 一视同仁（例：日历空白处点一下新建条目、删除条目都记）。读操作无论成功或失败都不记；失败、被拒绝或未提交的调用没有改动数据，也不记。
   - **系统来源（v1.16 用户确定）**：软件按规则自己做的后台改动也记，徽标「系统」（细框、无底色），筛选增加「仅系统」，展开详情最上面写「为什么会改」。包括：每天日界的活动日切换（想法超过天数自动进冷库、到回顾日生成本周回顾、首页重新出卡）；电脑休眠 / 关机恢复后补记离线时段（截断当时正在计的那条）；启动与唤回主窗口时的整理（有实质改动才记）。截图 `../UI参考截图/v0.3.0-beta.3-history-11-仅系统-活动日切换.png`。
   - **粒度**：用户的一个动作记一条（日历拖动在松手时、行内改描述在离开输入框时）；设置里 1 分钟内连续改同一项合成一条（显示「×N」，保留首次改前与末次改后）。
   - **来源徽标**：自动化分 `MCP` / `CLI`（黑底强调色字），统称「自动化」而非「AI」；手动为浅灰「手动」，后接来源小字（主窗口 · 页面 / 小窗 / 快速记录条）。正式版区分 MCP 与 CLI 需在请求中新增来源字段（接口约定变更，待 ADR）。
   - **调用方（v1.12）**：自动化徽标后显示是哪个 agent 调用的（如「MCP · Claude Desktop」「CLI · Claude Code」「CLI · 未识别」），不让模型在工具参数里自报：
     - MCP：读取握手时客户端自动发送的 `clientInfo`（name / version），SDK `getClientVersion()` 可取，15 个工具参数不变；按对照表换成显示名，表里没有的按原始名字显示。
     - CLI：依次取 `--agent <名字>` 参数或 `MONORAIL_AGENT` 环境变量（用户指定，优先）→ 已知 agent 设置的环境变量（如 `CLAUDECODE`、`CODEX_SANDBOX`，非统一标准，需维护对照表）→ 都没有记「未识别」。
     - 全部是对方自报、未验证，只用于显示和筛选，不作权限依据；不参与同一 `operation_id` 重试的冲突判断。
     - 界面：选「仅自动化」时，在来源分段后出现「AGENT 调用方」下拉（v1.13 由分段按钮改为下拉：调用方数量不固定，窄窗口不撑出横向滚动；带条数，按条数排序，未识别用细线隔开放最后，点外部或 Esc 收起）。窗口变窄时依次收起「连带 N 项」、英文小字、标题栏原型标签，搜索框换到下一行；960 与 820 宽实测无横向滚动；展开详情的「调用」顶部显示调用方、版本、「对方自报 · 未验证」与识别方式（MCP 握手 / 环境变量 / --agent 参数 / 无）；设置 09「最近调用」每行显示调用方，底部说明 `--agent` 与 `MONORAIL_AGENT`。
     - 开发影响（写入 ADR）：MCP / CLI 进程经管道发给主程序的内部请求加来源字段；CLI 新增 `--agent` 参数与环境变量检测；`receipts/` 现为 `version: 1` 严格格式，需升版或另存来源；各客户端 `clientInfo.name` 与环境变量取值需实测后补对照表（原型中的值为示意）。
   - **一行**：时刻 HH:MM:SS、来源、动作（删除类红字）、主体与小字、「连带 N 项」、◎ 定位、展开箭头。**展开**：「改动」改前 → 改后对照（新建改前为「—」，删除改后为红字「已删除」）；「连带改动」（截断、待机让位/回填、卡片状态、任务事项数等）；自动化另有「调用」：CLI 实际命令、方法、`operation_id`（可复制）与可折叠原始参数 JSON。
   - **范围**：默认最近 7 天、底部「再往前 7 天」；只看不撤销；**保留最近 180 天**（v1.15 用户确定），更早的操作历史自动清理，只清理操作历史本身，不动计时、卡片、`receipts/` 等业务数据。
   - **设置 09**：「接入概览」下新增「最近调用 RECENT CALLS」，列最近 5 条自动化改动，点一条跳到「列表 → 操作历史」、自动选「仅自动化」并展开该条；底部〔查看全部操作历史 →〕；从未调用时提示接入方式。
   - **原型**：`../原型/页面/history-prototype.html`（单文件、类名 `oh-` 前缀），参考截图 `../UI参考截图/v0.3.0-beta.3-history-01..11-*.png`；用户已于 2026-11-04 确认 UI（暂定稿，v1.14）。`UI风格规范.md` 未同步。
   - **开发前另需 ADR**（数据格式变化）：手动操作历史的存储位置与格式、是否与业务写入同一 journal 事务、退回稳定版的兼容、改前值的采集、`receipts/` 无索引时的列表与保留清理、小窗 / 快速记录条来源经窗口总线传递。
