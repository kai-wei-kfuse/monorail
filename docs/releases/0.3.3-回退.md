# 0.3.3 手动回退

0.3.3 启动时会先恢复未完成的 `.journal/` 事务，再把旧版数据从 Schema v2 升级到 **Schema v3**（`state.yaml` 与 `settings.yaml` 里 `schemaVersion: 3`，原多行想法拆分为首行标题与详情正文，原 `mainTasks: 1` 升级为 `2`）。如果 `state.yaml` 与 `settings.yaml` 已经是 v3，就不会重复迁移。

升级是单向的：0.3.2 读到 `schemaVersion: 3` 的文件会在启动时提示 `打不开这个数据目录：state.yaml: invalid state`，不能直接装回 0.3.2 继续打开同一个 v3 目录。要回到 0.3.2，请使用 0.3.3 升级前自动生成的 `backup/v2-…` 备份另起或恢复数据目录。

## 备份在哪

数据目录里的 `backup/v2-<升级时刻>-<编号>/`。升级时刻是 UTC，例如 `v2-2026-11-08T13-03-31-971Z-103c4e62-…`。

- 里面包含升级前除 `attachments/`、`.journal/`、`backup/` 以外的全部数据文件（`state.yaml`、`settings.yaml`、`records/*.md`、`tasks/*.md`、`cards/*.md`、`timelog/*.md`、`plans/*.yaml`、`reviews/*.md` 等），写入后均已逐文件读回比对校验。
- 备份目录根部有一份 `迁移记录.md`，记录了升级时刻、主线槽位变更与多行想法拆分摘要；这份是说明文件，回退时可跳过（即使留在根目录，0.3.2 的按子目录扫描也不会误读，但建议跳过以保持目录整洁）。
- `attachments/` 附件目录在 v2 → v3 升级时原样保留未改动，因此不在 `backup/v2-…/` 里；回退时直接从原数据目录复制 `attachments/` 即可。

## 会丢什么

升级到 0.3.3 以后新记的内容（在 0.3.3 期间新增或修改的计时条目、任务与事项卡、新建或编辑过的想法笔记与新附件）只保存在 v3 目录里，从 `backup/v2-…/` 恢复出的 v2 目录只包含升级那一刻之前的数据。

- 回退前，建议先在 0.3.3 里查看并导出或抄录升级后新增的重要想法笔记与计时记录。
- 原 v3 数据目录请改名保留、不要删除，以便随时对照或重新切回 0.3.3。

## 步骤

1. **完整退出 0.3.3**：若打开了想法笔记独立窗口，先保存或关闭所有想法窗口；然后在系统托盘图标右键菜单点「退出」（直接点主窗口右上角关闭只是隐藏到托盘，后台进程仍在运行）。确认此时数据目录 `.journal/` 下没有未完成的临时事务文件。
2. **改名保留当前 v3 数据目录**：把当前数据目录整个改名，例如 `F:\单轨` → `F:\单轨-v3备份`。不要删除它。
3. **新建空目录**：在原位置新建同名空目录（例如 `F:\单轨`），或者在 0.3.2 启动后选择一个新的空目录。
4. **复制 v2 备份文件**：打开 `F:\单轨-v3备份\backup\v2-…\`，把里面的 `state.yaml`、`settings.yaml`、`records`、`tasks`、`cards`、`timelog`、`plans`、`reviews` 等全部复制到新目录 `F:\单轨\`（可跳过 `迁移记录.md`）。
5. **复制附件（如有）**：如果 `F:\单轨-v3备份\attachments\` 存在，把它整个复制到 `F:\单轨\attachments\`。
6. **安装并启动 0.3.2**：安装 0.3.2（GitHub Release `v0.3.2` 的安装包），打开 0.3.2，确认首页、背包任务与想法池均正常加载且恢复为升级前状态。

## 重新换回 0.3.3

退出 0.3.2，把回退期间使用的 v2 目录改名留存（例如 `F:\单轨-v2回退期`），再把原先保留的 `F:\单轨-v3备份` 改回 `F:\单轨`（若想从回退期的 v2 目录重新升级，也可以直接用 0.3.3 打开该 v2 目录，0.3.3 会再次执行 v2 → v3 迁移并生成新的 `backup/v2-…`）。两个目录各自产生的后续修改不会自动合并。

## 验证情况与边界说明

- **代码与真实临时文件系统迁移演练（`evidence/0.3.3-p6-verification.test.ts`、`src/data/migrations/v3.test.ts`）**：已覆盖 ADR 0026 全部 6 种历史想法文本拆分分支、幂等重跑、坏输入失败回滚、逐写入边界崩溃恢复与 `backup/v2-…` 逐字节一致性校验。
- **隔离原生双版本可执行文件实测（`evidence/0.3.3-isolated/run-p7-supplement.mjs` → `results-p7-supplement.json`）**：
  1. 使用隔离版 `Monorail-0.3.3-isolated.exe` 对真实 v2 数据目录执行原生 v2 → v3 迁移并干净退出（`.journal/` 无未完成事务文件）；
  2. 使用真实旧版可执行文件 `Monorail-0.3.2-isolated.exe` 打开干净迁移后的 v3 目录（`v3-drill`），确认界面明确报错拦截（`打不开这个数据目录：state.yaml: invalid state`），且打开前后目录内全部文件（`state.yaml`、`settings.yaml`、`records/*.md`、`timelog/*.md`、`plans/*.yaml`、`backup/v2-*`）SHA256 哈希 100% 未被改动；
  3. 将 `backup/v2-*` 复制恢复至独立目录 `v2-restored-drill` 后再次用 `Monorail-0.3.2-isolated.exe` 打开，确认正常进入主页并在「背包 → 想法池」完整显示原 v2 多行想法（见截图 `evidence/0.3.3-isolated/shots/15-old-032-exe-rejects-v3-data.png` 与 `16-old-032-exe-opens-restored-v2-backup.png`）。
- **未宣称项**：本轮实测采用 `--debug --no-bundle --config` 隔离可执行文件验证，未运行 NSIS / MSI 安装器覆盖安装与卸载降级向导，亦未覆盖含有未完成 `.journal` 事务时直接用旧版强行混开的极端非正常关机场景。
