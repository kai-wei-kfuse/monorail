# 0.2.0 手动回退

0.2.0 启动时先恢复未完成的 journal，再把旧版数据从 v1 升级到 v2（`state.yaml`、`settings.yaml` 里 `schemaVersion: 2`）。如果 `state.yaml` 已经是 v2，就不会重复迁移。升级是单向的：0.1.x 读到 v2 的设置会在启动时报错，不能直接装回旧版继续用同一个目录。要回到 0.1.4，就用升级前的备份另起一个目录。

## 备份在哪

数据目录里的 `backup/v1-<升级时刻>-<编号>/`。升级时刻是 UTC，例如 `v1-2026-10-28T09-47-10-871Z-…` 是北京时间 17:47。

- 里面是升级前除 `attachments/`、`.journal/`、`backup/` 以外的全部文件，写入后逐个读回比对过。
- 备份目录根部多一份 `迁移记录.md`，写着升级时清空了哪些引用、改了哪些卡的状态；这份不是数据，回退时不要复制。
- 附件升级时不动，所以不在备份里，回退时从现在的目录拿。

## 会丢什么

升级以后新记的东西（计时条目、卡的完成、任务池的改动、新想法）都只在 v2 里，恢复出的 v1 目录不会包含它们。回退前在 0.2.0 的列表页抄下需要保留的计时记录；任务、卡和想法的改动从对应页面另行记录。回去后在 0.1.4 里手动补记；原 v2 目录继续保留。

## 步骤

1. 在托盘菜单里退出单轨（关窗口只是隐藏，进程还在）。
2. 把现在的数据目录整个改名，比如 `F:\单轨` → `F:\单轨-v2`。不要删，回退出问题还能换回来。
3. 新建一个空目录，用原来的名字 `F:\单轨`。
4. 把 `F:\单轨-v2\backup\v1-…\` 里的内容复制进去，**跳过** `迁移记录.md`。
5. 有附件的话，把 `F:\单轨-v2\attachments\` 整个复制到 `F:\单轨\attachments\`。
6. 卸载 0.2.0，安装 0.1.4（GitHub Release `v0.1.4` 里的 `monorail_0.1.4_windows-x86_64_setup.exe`）。0.1.4 的设置里没有「检查更新到旧版」，只能手动装。
7. 打开 0.1.4，确认能启动、首页和背包和升级前一样。数据目录没变，不用重新选。

## 换回 0.2.0

退出程序，把第 3 步新建的 `F:\单轨` 改名为一个未占用的目录名（例如 `F:\单轨-v1-回退后`），保留回退后新增的数据；再把 `F:\单轨-v2` 改回 `F:\单轨`，安装 0.2.0。它看到 `state.yaml` 的 `schemaVersion: 2`，不会再升级一次。两个目录里的后续改动不会自动合并。

## 验证情况

- 自动测试：备份恢复以后，冻结的 v1 读法能读，文件和原来逐字节一致（N2③，`evidence/n2-step3.md`）。
- 用户真实数据：2026-10-28 用当前代码在内存里重新迁移 `F:\单轨` 的 v1 备份，任务、卡和升级前的条目与真实目录里的 v2 完全一致（`evidence/n7-summary.md`）。
- 实际装回 0.1.4 并打开恢复出来的目录：**还没做**。
