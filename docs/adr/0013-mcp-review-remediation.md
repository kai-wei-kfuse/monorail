# ADR 0013：MCP 主审问题的共同不变量修复

状态：Accepted · 2026-11-03。用户授权主代理在 coder-3 宕机后接续修复；保留其已有改动。范围为 R1–R3、D1/D2，不重写为新的 CLI 架构。

## 决定
- 记录与卡片关联由共用 materialize 用例统一；已关联的卡片不再通过确定性 ID 重建。已带来源记录的卡不是可覆盖占位符。reconcile 不制造仅存在于内存的替代任务。
- 查询只读取完整已提交 snapshot，tasks/records 成为必需字段；部分 journal 失败后显式拒绝查询，不读文件半成品，也不返回正常空列表。快照发布前的派生投影若失败，必须禁止返回旧状态冒充最新状态。
- 用户命名的统计键使用 Map/无原型字典，输入输出校验均保留合法键，不添加名称黑名单。
- D1 定义共享的应用错误结构，经过主窗口、原生转发和 Node 客户端后仍保留 code/category/next_step/latest_context。MCP 将其放入 structuredContent 并提供相同文本表示，不将 JSON 藏在 Error.message 里要求调用方拆行。
- D2：只有 ENOENT 允许按需启动；EBUSY 表示连接忙，返回明确 PIPE_BUSY，不启动新实例或自动重放业务操作。已有启动连接等待不增加生成超时；清除其事件订阅，避免重复等待积累挂起回调。

## 验证
保留旧失败证据，新回归分别断言稳定关联、同版本快照/故障可见、特殊名称的协议往返、四种新旧协议/传输组合下的结构化冲突，以及忙管道不触发启动。使用隔离目录/内存数据，不操作日常单轨或安装发布。
