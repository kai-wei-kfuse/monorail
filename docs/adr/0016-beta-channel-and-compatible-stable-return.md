# ADR 0016：同产品 Beta 渠道与显式稳定版覆盖

状态：Accepted · 2026-11-03。用户授权实现加入/退出 Beta、GitHub 手动覆盖保留数据，并可选择稳定版覆盖安装。补充 ADR 0001/0002，不改变更新状态由原生唯一拥有的决定。

## 事实

- `private_release.rs` 当前读取正式 latest 或固定验收 tag，updater SDK 默认只接受较高 SemVer。
- 锁定的 updater 2.14.0 提供单次 `UpdaterBuilder::version_comparator`；全局 allow_downgrades 会放行所有不同版本，不符合本需求的显式选择。
- 当前产品名「单轨」、identifier `local.pixelrecord.app`、NSIS currentUser；生成 NSIS 模板支持允许降级，但目标 Beta/稳定安装包仍须实测，不能只凭旧0.1.3生成脚本下结论。
- 当前0.3.0与v0.2.5的state/settings/entity/timelog/journal格式无差异；新增receipts目录在旧版常规读取路径中被忽略。此为有限兼容证据，不代表未来任意版本可回退。
- 0.3.0-beta.3（2026-11-05 补充）：schema 仍为 2；新增 `history/` 目录与记录的两个可选字段 `created_via`、`history_logged_at`（ADR 0019「兼容与恢复」）。v0.2.5 源码审计结论为可读、可恢复、改写时保留新字段；2026-11-05 隔离安装实测矩阵 1–5 通过（真 0.2.5 打开、恢复、改写后交回 beta.3，见 `evidence/beta3-isolated/README.md`），第 6 条新版客户端连旧版桌面未测。`private_release.rs` 的 `AUDITED_COMPATIBLE_STABLE_VERSIONS` 仍列 `0.2.5`，与实测结论一致；这只是数据层面的有限证据，不代表退回后操作历史可用（旧版不显示也不补记）。

## 决定

1. 稳定版和 Beta 使用同一安装身份/路径/数据目录，不另建产品。「加入 Beta」是更新渠道偏好，不是账号申请或远程登记。偏好放在应用配置目录独立文件，不写入业务 settings.yaml；缺文件时稳定渠道，不因安装了 prerelease 自动视为已同意加入。
2. 普通 stable 检查只选正式稳定 Release。beta 渠道选择符合产品标签规则的稳定或 beta Release 中较新的版本；排除 draft、update-test、alpha/rc及不合法/矛盾标签。使用严格 SemVer，不按字符串或发布时间排序，不漏分页。
3. 「退出 Beta」立即持久化 stable 偏好，不自动降级；用户可留在当前构建等待更高稳定版，也可明确点击「安装稳定版」。只有这一显式动作才为已验证的目标稳定 Release 建立一次性、绑定版本/资产/快照的降级许可。比较器不得全局返回true或全局允许降级。
4. 更新状态快照同时区分当前构建类型、当前更新渠道、操作意图（正常更新/返回稳定版）与目标版本。切渠道会清除未安装的旧候选/下载结果；检查/下载/验签/安装繁忙期间禁止切换，原生端同样拒绝，避免旧异步结果覆盖新渠道。
5. 应用内安装沿用签名下载与保存封口；在主提交、快速记录/MCP写入和原生生命周期收尾后，对当前数据与应用配置建立可核验备份。备份失败不得启动安装器，准确解除封口或保留未知状态。无静默限长/跳过附件或自动恢复历史备份。
6. 同schema覆盖安装保留数据并继续使用Beta期间新增记录。需要回退数据格式的未来版本必须有明确迁移方案；本轮不实现通用逆迁移。兼容声明不足或已知不兼容时不能标为可保数据覆盖；仍允许退出渠道并等待。v0.2.5等旧稳定清单无新元数据时，只采用源码审计+实测建立的显式版本兼容表，不默认认为兼容。
7. 手动覆盖安装同样只替换应用文件，不初始化、删除、还原用户数据/config/目录授权。覆盖安装和卸载清数据是两条不同操作；文档引导直接运行同产品安装包，不先卸载。旧版没有入口的用户先这样安装带新入口的构建，再自行加入Beta。
8. 产品Beta标签采用 `v0.3.0-beta.N`，GitHub prerelease=true、make_latest=false；稳定版 `vX.Y.Z` prerelease=false。update-test 保留独立测试语义，不再把产品Beta与测试tag混用。每个Release自带签名资产与清单，正式渠道不读取Beta。

## 验证与边界

必须覆盖稳定→Beta→下一Beta、退出后等待稳定、显式Beta→较低稳定、稳定版本更高时正常升级、同基础号稳定高于beta、候选缺失/错误/签名失败、切渠道与异步竞态、重启持久化、草稿/写入封口以及手动安装保留数据。

隔离同产品测试身份内构建真实NSIS包，分别验证应用内与手动覆盖；安装前后哈希对比应区分安装器阶段的零业务文件修改，以及应用重新启动后合法的恢复/计时写入。不能用只改版本字符串、SDK模拟或启动成功替代安装验收。为支持无公开发布条件下的完整应用内 `updater.install` 验收，仅在编译期非正式发布构建（`debug_assertions`/`test`/`verify`）且应用 identifier 精确等于隔离测试身份 `local.pixelrecord.beta-channel-test` 时允许连接本机 `http://127.0.0.1:<port>` 回环 Release 夹具并使用临时测试公钥验签；正式发布构建与正式身份 `local.pixelrecord.app` 在编译期和运行期均强制使用 `https://api.github.com/repos/<owner>/<repo>/releases` 与生产公钥。

发布与安装用户日常版本不在本轮授权范围；可以准备构建、测试和发布材料，不自动push tag或创建公开Release。原 gh 登录机制沿用，不在本轮加入账号/遥测或改认证方案。
