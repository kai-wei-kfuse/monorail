# ADR 0009：MCP 完整本机能力、后台启动与模型调用契约

状态：Accepted · 2026-11-03。依据用户扩展需求与 `evidence/mcp-execution-plan-review-v2.md` 的无阻断复审。

版本修订（2026-11-03，最终）：用户在短暂采用 0.2.6 后，最终确定 MCP 版本为 0.3.0，并指定 coder-3 接手执行；当前计划为 `docs/stages/0.3.0.md`，架构决定不变。

## 背景
ADR 0008 描述已实现的 save_idea 原型。用户随后要求通用客户端、无需手动打开窗口、低成本模型易用，并授权选择现有功能扩展；未来会有手机端。

## 决定
采用 `docs/mcp/requirements-and-design.md` 当前设计，0.3.0 以 M4–M9 分阶段实施。保留单一桌面业务写入者、TypeScript 用例与 Rust 系统桥接；增加显式后台启动而不冒称 headless。业务契约不包含 Windows 路径与管道，手机同步另行设计。

SDK 以官方 v2 工厂与新旧协议互操作实测为基线；stdio 与 HTTP 共用工具实现。模型只复制服务签发的操作 ID、目标 ID 和状态令牌。回执与业务变更由同一 journal 提交，重复命中无写副作用；后置提醒/投影错误与持久化提交结果分别报告。

生命周期、数据格式与命令契约的具体实现须在对应里程碑补充验证；不因本 ADR 接受而把尚未实现的能力标成可用。完整当前决定及 N1–N4 见需求文档 §5。

## 对 ADR 0008 的替代范围
替代其“仅本机 stdio、用户预先手动运行应用、v1 SDK 为长期选型、工具无操作回执”作为未来限制的解释。保留已实现原型的历史事实、单写入者、禁止 MCP 直接写业务文件及事务复用原则。

## 验证与影响
M4–M9 需通过协议互操作、后台冷启动、恢复/并发、原生落盘、实际客户端及低价模型行为测试。此时仅设计审核通过；代码与测试证据仍按里程碑记录。远程、任务整理和手机同步在 stage-follow-ups 中保留。
