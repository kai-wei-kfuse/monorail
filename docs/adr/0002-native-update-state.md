# ADR 0002：原生更新状态是界面的唯一来源

- 状态：Accepted
- 日期：2026-10-27
- 分类：更新 IPC 合同和跨窗口状态同步的中等变更，补充 ADR 0001。

## 问题

原实现由 React 和 Rust 各自维护检查、下载和安装状态。重复请求被原生端拒绝后，前端 catch 会恢复 idle，而原任务仍可能执行，导致按钮再次可点且只显示「更新操作正在进行」。页面重载也无法读回真实任务。

## 决定

原生 Session 产生可读取、可订阅的完整状态快照。phase、busy 和更新版本从 Session 派生；步骤、下载字节、失败详情和步骤时间线由同一个 Store 管理。每次修改在一个互斥区内递增 revision，前端只接纳不早于已观察 revision 的快照，避免旧请求响应覆盖新事件。

界面明确显示检查中、下载中、验证中、安装准备中、安装中；细分读取登录、连接 GitHub、读取发布信息、读取清单、签名验证、等待事务、检查草稿、保存计时和启动安装器。当前步骤显示已等待秒数，完整步骤记录可展开。经过时间只用于显示，不是任意超时、自动降级或成功判定。

重复检查返回正在执行的任务快照，不另起请求，也不把 busy 当作操作失败。页面先订阅再读取快照；命令 IPC 失败后主动读取后台状态并显示通信错误，不能自行改为空闲或假定没有更新。

安装前先在原生状态中标明「等待当前保存完成」，再等待主提交队列。若安装准备失败，原生确认取消后才解除写入暂停。如果 IPC 中断导致原生安装状态未知，继续显式暂停写入并显示具体步骤及通信错误，避免安装时继续写文件。此边界由数据完整性要求产生，不是固定等待期限。

## 验证

回归覆盖事件先于初始快照、重复检查、旧响应乱序、IPC 失败保留繁忙状态、新观察者恢复下载进度、远程失败保留具体步骤，以及无法确认原生取消时禁止继续写入。真实验收必须从已安装版本经私有 Release 下载并覆盖到同一路径。
